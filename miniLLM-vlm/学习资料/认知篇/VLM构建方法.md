# VLM构建方法

> 本文是 VLM 的入门认知文章，重点回答：它是什么、比纯语言模型多了什么，以及如何通过训练获得视觉语言能力。文中的“构建”专指模型训练。
>
> 通过 Markdown 内的流程示意和例子建立整体认识，不要求先掌握算法公式或训练代码。整理日期：2026-09-08。

## 关键点

1. **VLM 是视觉语言模型。** 它学习视觉内容与语言之间的关系；本文重点讨论能够根据图片和问题生成文字回答的 VLM。
2. **它增加的是视觉信息来源，而不是取代语言能力。** 许多生成式 VLM 继续使用语言模型组织答案，只是回答还受到当前图片的影响。
3. **接上图片接口，不代表模型已经学会看图。** 图片需要被编码，视觉表示需要与语言网络适配，这种配合通常需要训练。
4. **构建 VLM 不一定从零训练所有模块。** 可以给已有 LLM 训练视觉接口、在已有 VLM 上继续训练，也可以从随机初始化开始预训练。
5. **看图回答、读出小字、理解视频和生成图片是不同能力。** 支持一种能力，不代表自动具备其他能力。
6. **有图像证据，仍可能回答错误。** 模型可能看不清、关联错、推理错或无依据地补全，需要用具体任务检验可靠性。

## 一、什么是 VLM

### 1.1 从“根据文字回答”到“根据视觉证据回答”

VLM 是 Vision-Language Model 的缩写，中文通常称为视觉语言模型。

先用一个具体例子理解：你想知道桌上有几个杯子。纯文本模型如果只收到这句话，并不知道你桌上的真实情况；你需要先用文字告诉它。具备相应能力的 VLM 则可以接收桌面图片，把图中的对象与“几个杯子”这个问题联系起来。

```text
纯文本模型：
用户描述桌面情况 → 模型根据描述回答

视觉语言模型：
桌面图片 + 用户问题 → 模型利用图片信息回答
```

区别不只是输入格式变了，而是**回答可以使用当前图像中的信息**。物体颜色、摆放关系、页面布局和图表走势，不必全部先由人转写成文字。

### 1.2 “视觉”包括什么

视觉输入可以是照片、截图、文档页面、图表，也可以是从视频中取出的画面。它们对模型提出的要求并不相同。

| 输入 | 可能的任务 | 额外需要的能力 |
|---|---|---|
| 日常照片 | 描述场景、询问对象属性 | 识别物体与关系 |
| 文档或票据 | 读取字段、理解表格 | 识别文字、保留布局 |
| 图表 | 比较趋势、解释数值 | 联系图例、坐标和数据 |
| 软件截图 | 说明界面内容、寻找按钮 | 识别控件及空间位置 |
| 多张图片 | 比较差异、匹配对象 | 区分图片归属与指代 |
| 视频 | 描述动作、定位事件 | 联系帧顺序与时间 |

表中是 VLM 可承担的任务方向，并不表示每个 VLM 都能可靠完成全部任务。模型实际能力取决于输入设计、训练内容与评估结果。

### 1.3 并非所有 VLM 都是聊天模型

广义 VLM 包括不同类型的图文模型。比如 CLIP 学习图片和文本是否匹配，适合做图文检索或提供视觉表征；这种双编码器结构本身不会连续生成一段聊天回答。[CLIP 原始论文](https://arxiv.org/abs/2103.00020)

```text
图文匹配：
图片 + 候选描述 → 判断哪些描述更匹配

图文生成：
图片 + 问题 → 生成文字回答
```

日常讨论“能看图的语言模型”时，通常指第二类。后文的构建与训练说明，也以生成式视觉语言模型为主。

## 二、VLM 与 LLM 有什么区别

### 2.1 先明确比较对象

LLM 是 Large Language Model，即大语言模型。在实际命名中，一些支持多模态的模型也会被统称为 LLM，因此两个名称并不是严格互斥的类别。

为了讲清区别，本文将 **VLM 与“只接收文本的 LLM”比较**。许多 VLM 本身就包含一个 LLM，视觉能力是围绕它扩展出来的。

| 比较维度 | 纯文本 LLM | 生成式 VLM |
|---|---|---|
| 输入信息 | 文本及已经转成文本的资料 | 文本与经过编码的视觉内容 |
| 当前事实从哪里来 | 用户文字、检索结果、工具输出等 | 还可以来自当前图片 |
| 常见处理链路 | 文本表示 → 语言模型 | 视觉表示与文本表示 → 图文融合 → 语言生成 |
| 训练数据 | 文本、对话、代码等 | 还需要图文关系与视觉任务数据 |
| 新增难点 | 语言理解、知识和推理 | 感知细节、空间关联、跨模态协作 |
| 常见错误 | 误解文本、知识错误、无依据补全 | 还可能看错物体、读错文字、关联错位置 |
| 计算成本 | 受模型与文本长度影响 | 还受分辨率、图片数量和视频帧数影响 |

### 2.2 它们共享什么

许多生成式 VLM 仍然采用语言模型的基本输出方式：预测下一个 token，再根据已有内容继续生成。Token 可以粗略理解为模型处理的文本片段，并不一定对应一个完整汉字或单词。

所以，接入视觉后，语言知识、表达能力、指令遵循和推理能力依然重要。图片提供额外证据，语言网络需要把这些证据与问题联系起来，组织成答案。

```text
已有语言能力：理解问题、组织表达、使用知识
                         +
视觉输入能力：获取当前画面中的内容与关系
                         +
跨模态协作：让问题与视觉证据建立有效联系
                         ↓
                  看图回答的能力
```

这说明 VLM 不是简单地在 LLM 外面增加一个上传按钮，而是新增了可学习的信息处理通路。

### 2.3 看见新图片，不等于永久学会新知识

把一张图片发给 VLM，通常只是让它在本次推理中使用图片作为上下文，不会自动修改模型参数。

可以把两者分开：

- **推理**：使用已有能力处理当前输入，形成回答。
- **训练**：使用数据与反馈调整参数，改变模型之后处理任务的方式。

连续上传许多图片，并不等于给模型完成了一次微调。应用保存了历史图片，也不代表这些内容已进入模型参数。

## 三、VLM 怎样从图片得到回答

### 3.1 一条常见的三模块链路

```text
图片 → 视觉编码器 → 连接器 ─┐
                           ├→ 语言模型 → 回答
问题 → 文本处理 ────────────┘
```

这是常见的模块化构建方式，而不是所有 VLM 的唯一结构。LLaVA 将视觉编码器与 LLM 连接并进行视觉指令训练，就是一个代表性例子。[LLaVA 原始论文](https://arxiv.org/abs/2304.08485)

| 模块 | 负责什么 | 不应误解为什么 |
|---|---|---|
| 视觉编码器 | 把像素转换为有用的视觉特征 | 不是直接生成最终答案 |
| 连接器 | 适配或整理视觉特征，使语言网络可以使用 | 不一定先翻译成文字描述 |
| 语言模型 | 联系问题与视觉信息，生成文本 | 不会仅凭接上模块就自然配合好 |

### 3.2 视觉特征不是一篇隐藏的说明书

视觉编码器输出的是数值表示。它们可以承载对象、颜色、位置和文字等信息，但通常不能直接当成一句人类语言阅读。

“视觉 token”可以理解为在模型处理中占据一个位置的视觉表示。说一张图片占若干个视觉 token，不是说图片已经变成了同样数量的词。

如果系统先把图片生成一段说明，再把说明交给纯文本模型，后者只能使用说明中保留的内容。直接接入视觉特征的 VLM，则有机会在问题条件下利用更丰富的图像信息。

### 3.3 两个现成模型为何不能随便拼接

视觉与语言模块各自训练，内部表示的组织方式可能不同。就算输出宽度相同，也不意味着语言模型能够正确解释视觉模块给出的数值。

连接器和跨模态训练就是为了解决这种不匹配。BLIP-2 展示了利用已训练的视觉、语言主干，并学习中间桥接模块的路线，说明构建 VLM 可以复用成熟模块。[BLIP-2 原始论文](https://arxiv.org/abs/2301.12597)

不过，桥接模块只能利用已有输入。图片预处理时已经丢失的小字，不能期待它可靠地重新补出来。

### 3.4 为什么同一张图片可以回答不同问题

对一张餐馆照片，可以问“有几张桌子”，也可以问“出口在哪边”。模型需要根据问题联系不同视觉信息，而不是只给图片生成一次固定类别判断。

这类按问题使用图像的能力，需要在训练中获得。仅见过概括性描述的模型，不一定已经学会精确计数、文字读取或复杂空间问答。

## 四、VLM 与 OCR、图像生成、Agent 的关系

### 4.1 OCR 加 LLM，是另一种可用的信息链路

OCR 是光学字符识别，主要把图片中的文字转成可处理的文本。系统可以先运行 OCR，再让 LLM 阅读识别结果。

```text
OCR + 纯文本 LLM：
文档图片 → 提取文字及可选布局信息 → LLM → 回答

生成式 VLM：
文档图片 → 视觉表示 → 与问题融合 → 回答
```

如果任务只需要准确提取几个文字字段，OCR 与规则或 LLM 组合可能就能解决问题。如果任务还依赖图表形状、对象外观或布局关系，只有文字转写可能不够。

两种路线也可以组合：让 VLM 利用视觉信息，同时参考 OCR 结果。是否采用组合，应由目标数据上的效果、成本和维护要求决定。

### 4.2 能理解图片，不等于能生成图片

看图回答主要是视觉输入到文本输出。生成图片还需要适合表达视觉输出的机制、图像解码路径及相应训练。

```text
视觉理解：图片 + 问题 → 文本
图像生成：文字或其他条件 → 图片
```

同一系统可以支持两者，但它们不是自动相伴的能力。不要因为模型名字带有“多模态”，就认定它支持所有输入输出组合。

### 4.3 能看界面，不等于能操作电脑

VLM 可以为界面理解提供能力，例如识别截图中的按钮。执行点击、输入文字、观察操作结果，还需要外部工具与控制流程。

```text
界面截图 → 识别状态 → 决定动作 → 工具执行
               ↑                     ↓
               └──── 新截图或反馈 ────┘
```

这构成视觉 Agent 的一种工作方式。VLM 可以参与感知与决策，但单独一个模型权重文件并不包含完整的操作系统、工具接口和执行逻辑。

## 五、训练 VLM 的三种路径

训练路径首先取决于起点：只有语言与视觉模块各自的能力，已经具备图文协作能力，还是尚无预训练基础。三个起点决定了训练要补齐什么。

### 5.1 路径一：基于已有 LLM 训练视觉能力

如果已有自己的纯语言 Base，希望复用它，就需要选择视觉编码器、连接模块和输入形式，再训练图文协作。

```text
已有视觉编码器 ─┐
               ├→ 设计连接方式 → 图文对齐 → 视觉指令训练
已有语言模型 ───┘
```

这条路线要处理的是从纯语言到视觉语言的能力扩展。关键工作包括：

1. 选择适合目标任务的视觉输入与编码器。
2. 让视觉表示进入语言模型，并保持文本处理一致。
3. 准备图文数据，先验证视觉输入确实影响输出。
4. 通过任务数据训练问答与指令行为。
5. 检查新图像上的表现，以及原有语言能力是否保持。

LLaVA、BLIP-2 等公开工作提供了不同的连接和训练思路。它们表明复用既有模块是一条可行路线，但不意味着任何两个模型直接拼接都能工作。[LLaVA](https://arxiv.org/abs/2304.08485)、[BLIP-2](https://arxiv.org/abs/2301.12597)

### 5.2 路径二：在已有 VLM 上继续训练

这条路径以已经具备图文协作能力的模型权重为起点，通过新的数据和参数更新，训练特定领域或任务能力。

```text
已有 VLM 权重 + 领域图文数据或视觉指令数据
                         ↓
              继续预训练或监督微调
                         ↓
               更适应目标任务的 VLM
```

例如，原模型能描述票据，却不能稳定提取指定字段，可以准备相应的图片、问题和理想答案进行训练。更新范围可以是适配器、部分主干或更广泛的模型参数。

与第一条路径相比，这里的起点已经包含视觉接口和图文对齐能力，训练重点是领域适应、任务扩展或行为改善。仍需检查新任务表现，以及原有能力是否因训练而退化。

### 5.3 路径三：从随机初始化开始预训练

严格意义上的全模型从零训练，需要让视觉与语言主干从随机参数学习基础能力，再建立跨模态协作。可以先分别预训练模块，再进行图文训练，也可以设计更早融合的多模态训练流程。

```text
随机初始化的视觉与语言模块
              ↓
利用图像、文本和图文数据学习基础能力与跨模态关系
              ↓
视觉指令训练及后续能力优化
```

这条路径能够更广泛地控制模型与数据设计，同时需要承担基础能力学习、训练稳定性和计算规模的成本。

“联合训练”描述多个模块共同更新，不代表它们一定从随机参数开始。前两条路径同样可以进行联合训练。因此，应分别说明**初始化来源**和**参数更新范围**。

### 5.4 三条训练路径的区别

| 路径 | 训练起点 | 主要训练任务 |
|---|---|---|
| 基于 LLM 训练视觉能力 | 分别训练好的语言与视觉模块 | 建立跨模态对齐，再训练视觉任务行为 |
| 在 VLM 上继续训练 | 已有图文协作能力的模型权重 | 领域继续预训练、指令微调与能力扩展 |
| 从零预训练 | 随机初始化的模型参数 | 学习基础表征、语言能力及跨模态关系 |

三条路径都通过数据和反馈更新参数，区别在于复用多少已有能力、从哪个阶段开始学习。训练方案应围绕目标能力、数据条件与计算预算选择。

## 六、训练过程究竟在教什么

### 6.1 先建立一个阶段地图

```text
取得视觉与语言基础能力
           ↓
图文对齐：让两个模块能够合作
           ↓
按需要扩大多模态训练：覆盖更多输入和任务
           ↓
视觉 SFT：学会按照问题和指令回答
           ↓
可选的反馈优化：改善事实性与任务表现
```

这是理解训练目的的地图，不是每个项目都必须逐步执行的固定配方。有些阶段会合并，有些模型已有足够的初始化，可以省去独立的接口预热。

### 6.2 Pretrain 可能指不同的工作

| 名称所指的工作 | 主要学习什么 |
|---|---|
| 视觉编码器预训练 | 怎样提取有用的视觉特征 |
| 语言模型预训练 | 语言规律、知识与生成能力 |
| 连接器图文对齐 | 怎样让语言网络使用视觉表示 |
| 多模态继续预训练 | 怎样更广泛地联合处理图文 |

因此，不能只看到脚本名中有 pretrain，就认定它重新训练了整个模型。需要查看数据、参数更新范围和目标。

### 6.3 对齐与 SFT 的区别

对齐阶段主要解决“图像能否被语言网络有效使用”。一种常见做法是根据图片预测描述，先让连接器建立适配。

SFT 是监督微调，进一步用“图片、问题、理想回答”训练具体任务行为。

```text
描述训练：
图片 → “桌上有杯子和一本书。”

指令训练：
图片 + “书在杯子的哪一边？” → “在左边。”
图片 + “只列出物品名称。”   → “杯子、书。”
```

两者可以使用相似的文本预测方式，差别更多在于模型被要求完成什么。会概括一张图，并不等于已经会按各种指令选择证据和控制输出。

### 6.4 冻结、微调与 LoRA 不在同一层级

“冻结”说明哪些参数暂时不更新，“SFT”说明用什么任务形式训练，“LoRA”说明一种减少可训练参数的适配方式。它们可以组合使用。

只训练连接器时，视觉和语言主干仍会参与计算。语言模型虽然不更新自身参数，仍需要把答案误差传回连接器。可训练参数少，也不代表两个主干从显存和计算中消失。

入门时，更应先理解更新范围的作用：更新少，资源压力较低但适应自由度受限；更新多，可以改变更多行为，但需要更充分的数据和验证。

### 6.5 图片输入、训练与推理各自改变什么

| 行为 | 主要改变什么 |
|---|---|
| 换一张输入图片 | 改变这次回答可以使用的视觉证据 |
| 改写问题或提示 | 改变当前任务和表达要求 |
| 微调模型 | 改变参数，影响之后的任务行为 |
| 增加工具流程 | 改变系统获取信息、执行与验证的方式 |

如果问题只是输出格式不明确，可能先改提示就有效；如果输入中的小字根本看不清，应先检查图像处理；如果模型长期不适应特定任务，才进一步分析训练数据与参数适配。

<a id="system"></a>

## 七、训练 VLM 还需要准备什么

### 7.1 先定义要解决的问题

“训练一个能看图的模型”还不够具体。应该进一步明确输入是什么、需要输出什么、怎样判定正确。

例如，以下三个目标所需方案就不一样：

- 描述日常照片的主体内容。
- 从扫描发票中提取编号、日期和金额。
- 根据多张图判断同一对象发生了什么变化。

目标会影响视觉分辨率、是否需要多图、数据标注、输出格式和评估方式。

### 7.2 一个完整的训练流程

```text
明确任务与合格标准
        ↓
收集代表性样本，建立独立评估集
        ↓
确定训练起点、初始化权重与参数更新范围
        ↓
准备训练数据，验证图片处理与模型输入
        ↓
小规模试跑，检查训练反馈与保存恢复
        ↓
执行正式训练，定期验证并保存模型
        ↓
评估新图像上的能力，根据错误调整数据或训练方案
```

评估集应在训练前考虑。否则容易反复依据训练样本调整方案，却不知道是否适用于新图片。

### 7.3 数据不能只看数量

一张图配多条问答，可以贡献多条训练样本，但并不等于多张独立图片。数据还要关注清晰度、场景覆盖、语言、任务类型和答案质量。

特别需要检查：答案能否从图中得到支持。如果图片没有显示生产日期，却写了一个确定日期作为标签，模型会被训练成对不可见信息也给出肯定答案。

训练与验证还应避免共享相同或近似图片。文档、视频也应根据来源划分，防止把重复内容误当作泛化能力。

### 7.4 图像数量与分辨率也属于成本因素

视觉输入需要编码，保留的视觉位置还要被后续网络读取。图片更多、分辨率更高、视频帧更多，通常会增加计算与内存需求。

因此，不能只按语言主干参数量估计 VLM 的运行成本。也不能假定图片越大越好：额外输入需要与模型支持的形式和实际任务收益匹配。

## 八、怎样判断它是否真正看懂

### 8.1 不要把一句流畅描述当成能力证明

模型可能正确描述整体场景，却读错小字；也可能猜中常见答案，却没有使用当前图片。需要根据任务设置对照。

```text
固定问题：“杯子是什么颜色？”

图片 A：红色杯子 → 理想回答：红色
图片 B：蓝色杯子 → 理想回答：蓝色
图片 C：杯子被遮挡 → 理想回答：无法确定
```

这是评估思路，不是实测结果。关键是输出是否随视觉证据合理变化，以及证据不足时是否能够说明限制。

### 8.2 三层检查

| 层次 | 检查什么 | 示例 |
|---|---|---|
| 感知 | 是否读对输入内容 | 文字、颜色、数量是否正确 |
| 关联与推理 | 是否联系对对象和问题 | 价格是否对应正确商品 |
| 表达与行为 | 是否忠实、符合指令 | 是否只输出需要的字段，是否编造 |

这样可以避免一遇到错误就笼统地认为模型“不够大”。很多问题更直接地来自输入清晰度、任务数据或关联能力。

### 8.3 VLM 仍然有能力边界

图片可能模糊、遮挡或缺少信息，模型也可能过度依赖常识。高分辨率、更多数据和更强语言能力可以帮助一些任务，但不能保证所有错误都消失。

尤其要区分“图片展示了什么”和“模型据此推测了什么”。看到一个人在跑步，不足以确定其身份、职业或真实动机；看到外观相似的物体，也不代表能判断其内部状态。

可靠应用需要围绕实际问题评估，而不是只依据模型名称、少量演示或通用描述效果。

## 九、常见误解与后续阅读

| 容易产生的误解 | 更准确的理解 |
|---|---|
| VLM 是完全替代 LLM 的另一种模型 | 很多生成式 VLM 包含 LLM，并扩展视觉输入 |
| 能上传图片，就说明模型会看图 | 还要有有效的视觉编码、适配与训练 |
| 视觉 token 就是图片转成的文字 | 常见实现中它是连续视觉表示 |
| 给模型看很多图片，就完成了训练 | 普通推理不会自动更新模型参数 |
| 从头构建 VLM 就要从零训练全部权重 | 可以复用已有模块，仅训练新增部分或继续适配 |
| 会描述照片就一定会 OCR、视频和图像生成 | 这些需要对应输入、输出设计与训练 |
| 只训练一小部分参数，整个模型就很小 | 冻结主干仍然需要加载并参与计算 |

原始资料可先阅读 [CLIP](https://arxiv.org/abs/2103.00020)、[LLaVA](https://arxiv.org/abs/2304.08485) 和 [BLIP-2](https://arxiv.org/abs/2301.12597)。它们分别帮助理解图文表征、视觉指令学习，以及复用现成模块进行跨模态适配。

## 十、本项目处于什么位置

miniLLM-vlm 属于“给已有 LLM 接入视觉能力”这条路径：复用 miniLLM 训练出的语言 Base，连接已经训练好的 SigLIP2 视觉编码器，通过中间的 MLP 适配视觉表示。

```text
SigLIP2 视觉编码器〔冻结〕
             ↓
       MLP 连接器〔训练〕
             ↓
miniLLM 语言 Base〔冻结〕 → 图片条件下的文本回答
```

当前 Pretrain 的主要目标是建立图文接口，训练重点在连接器。它不是重新从零训练视觉和语言主干，也不代表已经完成通用视觉助手所需的全部指令训练与评估。

miniLLM-vlm 使用自身的独立代码加载 Base 等模型文件，运行时不依赖父项目 miniLLM 的源码。后续要提升哪些能力，应由目标任务、训练数据和验证结果决定。
