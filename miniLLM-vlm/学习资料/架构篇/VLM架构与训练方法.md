## 一、VLM 在语言模型上增加了什么

### 1.1 从文字生成到基于图像证据生成

纯语言模型根据文本上下文生成后续内容。生成式视觉语言模型 VLM 则在这个过程中加入图像信息，让回答同时受到图片和问题的影响。

```text
纯语言模型：
文字问题 → 文本表示 → 语言模型 → 回答

生成式 VLM：
图片 → 视觉编码器 → 连接器 ─┐
                           ├→ 语言模型 → 回答
文字问题 → 文本表示 ────────┘
```

例如，问题是“牛肉面多少钱”：语言模型仅凭常识可以猜测价格，VLM 则应该读取当前菜单上的标价。换一张价格不同的菜单，回答也应发生相应变化。

因此，VLM 的关键不只是能接收图片，而是**让图像中的证据参与答案生成**。整个系统需要完成感知、信息适配、图文关联和语言表达。

### 1.2 VLM 不只指看图聊天模型

| 类型 | 输入与输出 | 主要用途 |
|---|---|---|
| 图文表征模型 | 图片、文本 → 表示与匹配程度 | 图文检索、分类、提供视觉特征 |
| 生成式理解模型 | 图片、问题 → 文本回答 | 图片描述、视觉问答、文档理解 |
| 理解与生成统一模型 | 图文输入 → 文本或图像 | 同时处理视觉理解与图像生成 |

CLIP、SigLIP 主要属于第一类。它们学习图像和文本之间的关系，其双编码器本身并不负责逐字生成回答。本文重点讨论第二类，也就是在视觉输入条件下生成文本的模型。[CLIP](https://arxiv.org/abs/2103.00020)、[SigLIP](https://arxiv.org/abs/2303.15343)

## 二、三个核心模块怎样分工

### 2.1 视觉编码器：把像素变成有用的表示

图片最初是一组像素数值，语言模型不能直接把这些数值当作文字理解。视觉编码器负责从中提取适合后续使用的信息。

常见的视觉 Transformer，也叫 ViT，处理过程可以概括为：

```text
原始图片
   ↓
缩放、归一化等预处理
   ↓
划分为小块 Patch
   ↓
每块转换成数值表示，并加入位置信息
   ↓
多层视觉 Transformer：各位置交换信息
   ↓
一组视觉特征
```

Patch 是图片中的小块，不是完整物体。一个物体可能跨越多个 patch，一个 patch 也可能包含多个对象的局部。经过网络处理后，每个位置的特征还可以包含周围乃至整张图的信息。[ViT](https://arxiv.org/abs/2010.11929)

这里的“特征”是一组数值，不是事先写好的“这是一只猫”等文字标签。颜色、形状、空间关系和语义信息可能分散在许多位置与数值之中。

**为什么保留多个位置？** 因为“概括整张图”和“回答局部问题”需要的信息量不同。判断图片是不是菜单，可以依靠整体特征；读取右下角的价格，则需要保留局部信息。过早把整张图压成一个总体表示，可能限制细节问答。

### 2.2 视觉编码器已经预训练过，为什么还需要 VLM 训练

CLIP、SigLIP 等视觉模块通过图文学习获得有语义关联的视觉特征，SigLIP 2 又结合了额外目标以改善表征能力。也有主要依靠图像自身规律学习的视觉模型。[SigLIP 2](https://arxiv.org/abs/2502.14786)、[DINOv2](https://arxiv.org/abs/2304.07193)

但视觉模块与语言模型通常分别训练。前者有能力提取图像信息，不代表后者已经知道如何使用它。

```text
视觉编码器已经学会：怎样表示图像内容
语言模型已经学会：怎样处理语言并生成文字

还缺少：怎样让语言模型读取这些视觉表示
```

所以，复用成熟模块可以节省基础训练成本，却不能省略跨模态适配这一问题。

### 2.3 连接器：把视觉表示接入语言模型

连接器通常位于视觉编码器与语言模型之间。它处理已经提取出的特征，让这些特征适应语言模型的输入方式。

即使两个模型的隐藏宽度相同，也可能需要连接器：每个位置都用 768 个数字表示信息，并不意味着这些数字的组织方式、尺度和语义作用一致。

连接器的两项作用需要分开：

```text
作用一：特征适配
N 个视觉位置 → 投影 / MLP → N 个适配后的视觉位置
位置数量可以不变，主要改变表达方式。

作用二：信息压缩
N 个视觉位置 → 合并 / 重采样 → 较少的视觉位置
减少后续读取成本，同时形成信息瓶颈。
```

| 连接方式 | 主要工作 | 需要理解的取舍 |
|---|---|---|
| 线性投影 | 对每个位置进行简单映射 | 结构小，适配能力相对有限 |
| 两层 MLP | 对每个位置进行非线性适配 | 简洁，通常不改变位置数量 |
| 合并或池化后投影 | 先减少位置，再适配表示 | 减少成本，但细节可能受损 |
| Q-Former / Resampler | 用学习出的读取机制提取较短表示 | 长度可控，结构和训练更复杂 |

原始 LLaVA 使用线性投影，LLaVA-1.5 改为两层 MLP；BLIP-2 使用 Q-Former，Flamingo 使用 Perceiver Resampler。它们不是单纯“复杂程度不同”，也对保留多少视觉信息作出了不同选择。[LLaVA](https://arxiv.org/abs/2304.08485)、[LLaVA-1.5](https://arxiv.org/abs/2310.03744)、[BLIP-2](https://arxiv.org/abs/2301.12597)、[Flamingo](https://arxiv.org/abs/2204.14198)

Q-Former 一类模块可以理解为：由若干可学习的查询位置，从较长视觉表示中提取信息。这些查询并不是人工规定好的物体类别，也不一定直接由用户问题产生，具体要看模型设计。

### 2.4 语言模型：把图像信息与问题联系起来

语言模型继续承担序列处理和文本生成，只是可读取的上下文增加了视觉信息。

对同一张图片，不同问题要求使用不同信息：

| 问题 | 模型需要完成的关联 |
|---|---|
| 这是什么场景？ | 综合整体视觉信息 |
| 左边的人穿什么颜色？ | 联系对象、位置与颜色 |
| 价格是多少？ | 联系文字、数字及其归属 |
| 两张图有什么变化？ | 联系跨图对象和差异 |

Attention 帮助模型读取相关上下文，后续网络继续处理这些表示，最后生成回答。这里的图文联系由多层网络共同形成，不能简单地把某一个注意力头解释为某种固定的人类技能。

**三个模块的能力需要匹配。** 视觉侧没有保留下来的细节，连接器无法可靠补回；已经保留的视觉信息，如果适配不足，语言侧也可能不会用；语言模型本身的表达和推理能力同样影响结果。

## 三、视觉信息怎样与文字融合

连接器说明“视觉特征经过什么处理”，融合机制说明“这些特征在哪里被语言模型读取”。这是分析架构时最重要的区分之一。

### 3.1 输入层融合：组成同一条序列

这条路线先把图片与文字转换为兼容的表示，再交给同一个语言模型主干。

```text
图片 → 视觉编码器 → 连接器 → 视觉表示 ─┐
                                      ├→ 组合输入序列
问题 → Tokenizer → 文本嵌入 ──────────┘
                                                ↓
                                  多层语言 Transformer
                                                ↓
                                          生成答案

序列示意：
[提示文字] [视觉位置 1 ... N] [问题] [回答前缀]
```

它的优点是容易复用既有语言模型。视觉位置与文本位置进入同一套后续处理，回答可以通过注意力读取前面的图片信息。

代价是视觉位置占用公共序列空间。图片更多、分辨率更高或保留特征更多，通常会增加语言侧计算和缓存开销。LLaVA 系列是这条路线的典型代表。[LLaVA-1.5](https://arxiv.org/abs/2310.03744)

### 3.2 图像占位符起什么作用

`<image>` 常常只是数据层的标记，用来告诉程序图片应放在什么位置。有些实现把它展开为多个占位位置，再用视觉向量替换原来的查表嵌入。

```text
文本标记：     <image> 请描述图片
                  ↓
预留位置：     [占位] [占位] ... [占位] [问题]
                  ↓ 替换为真实图像特征
实际输入：     [视觉] [视觉] ... [视觉] [问题]
```

这里说的“视觉 token”，通常是占据一个序列位置的连续数值表示，不是一个汉字，也不必对应词表里的某个词。

因此，图片不是先被翻译成一段隐藏的 caption，再让 LLM 读取。先生成文字描述再交给另一个模型，是另一种系统设计，其信息受到那段描述的限制。

### 3.3 跨注意力融合：在语言层读取独立视觉信息

另一条路线保留单独的视觉分支，在语言模型内部增加读取视觉信息的模块。

```text
图片 → 视觉编码器 → 视觉重采样 → 独立视觉表示
                                             │
                                             ↓
文本 → 语言层 → 跨注意力读取 → 后续语言层 → 回答
```

语言侧处理到相应层时，以当前隐藏状态读取视觉特征。Flamingo 使用这种门控跨注意力设计，把视觉信息接入既有语言网络。[Flamingo](https://arxiv.org/abs/2204.14198)

它不要求把全部视觉特征放进文本输入序列，但需要新增网络层，并管理视觉分支的计算与访问方式。视觉读取本身仍然有成本。

需要注意：输入层融合也会产生图文之间的注意力联系，但这不等于它增加了一个结构独立的 Cross-Attention 层。**信息发生交互，与采用独立跨注意力模块，是不同层面的描述。**

### 3.4 编码器—解码器与多层视觉注入

还有两类值得认识的变化：

- **图像编码器—文本解码器**：编码器形成视觉表示，解码器在生成文字时读取它。Pix2Struct 是代表之一，重点探索截图、文档和界面相关理解。
- **多层视觉注入**：把不同深度的视觉特征送入多个语言层，而不只在输入端送一次。Qwen3-VL 的 DeepStack 体现了这类设计，但其残差注入不能与 Flamingo 式跨注意力混称。

来源：[Pix2Struct](https://arxiv.org/abs/2210.03347)、[Qwen3-VL](https://arxiv.org/abs/2511.21631)。

无论哪种结构，都可以用同一组问题分析：图像在哪里编码、保留多少信息、在哪里融合、语言模型如何生成输出。

## 四、高分辨率、多图和视频怎样改变架构

### 4.1 分辨率决定什么信息能够进入模型

图像理解与细节读取的要求不同。把整页文档缩小，模型可能仍认得出“这是一张发票”，却看不清金额。

```text
固定尺寸：
原图 → 整张缩放 → 固定数量的视觉特征

多块输入：
原图 → 全局缩略图 + 从原图切出的局部块 → 更多视觉特征

动态分辨率：
原图 → 按形状与预算构建可变网格 → 可变长度视觉特征
```

高分辨率方案需要同时解决三个问题：如何保留细节，如何告诉模型这些细节的位置，以及如何控制新增计算。不能只调大输入尺寸，就认定既有编码器获得了可靠的高清能力。

LLaVA-OneVision 与 Qwen2.5-VL 对这些问题给出了不同的视觉表示方案，包括动态输入、局部处理和特征压缩。[LLaVA-OneVision](https://arxiv.org/abs/2408.03326)、[Qwen2.5-VL](https://arxiv.org/abs/2502.13923)

### 4.2 多图需要维护信息归属

两张图片各自能被识别，不代表模型能正确比较它们。模型还需要知道某个对象、价格或文字来自哪一张图。

所以，多图架构与数据要共同表达图片边界、顺序和指代。训练中也要出现比较、对应和跨图问答，才能把单图能力转化为多图协作能力。

### 4.3 视频需要维护时间关系

```text
视频 → 采样画面 → 提取每帧视觉信息
                         +
                   帧顺序与时间信息
                         ↓
              联系前后变化，理解事件
```

“杯子在桌上”和“杯子被拿起”是不同时间的状态。理解视频还需要知道事件顺序、发生时间以及跨帧对象是否一致。

增加帧数可以保留更多线索，也增加读取成本。现代视频 VLM 因而同时考虑帧采样、每帧特征数量和时间表示。[Qwen2.5-VL](https://arxiv.org/abs/2502.13923)、[Qwen3-VL](https://arxiv.org/abs/2511.21631)

## 五、代表性架构的设计区别

| 代表模型 | 结构重点 | 主要设计意图 |
|---|---|---|
| LLaVA / LLaVA-1.5 | 视觉编码器 + 线性投影或 MLP + LLM | 用简洁接口复用已有视觉与语言能力 |
| BLIP-2 | 视觉编码器 + Q-Former + LLM | 提取较短、适合语言模型使用的视觉表示 |
| Flamingo | 视觉重采样器 + 语言层内跨注意力 | 通过独立视觉分支支持图文交互 |
| LLaVA-OneVision | 延续简洁主干，组织不同视觉场景 | 协调单图、多图和视频的表示与训练 |
| Qwen2.5-VL / Qwen3-VL | 动态视觉输入、位置及融合设计 | 改善细节、时间和长输入处理 |
| InternVL3.5 | ViT–MLP–LLM 与广泛联合训练 | 通过数据、预训练和后训练扩大能力 |

参考：[LLaVA-1.5](https://arxiv.org/abs/2310.03744)、[BLIP-2](https://arxiv.org/abs/2301.12597)、[Flamingo](https://arxiv.org/abs/2204.14198)、[OneVision](https://arxiv.org/abs/2408.03326)、[Qwen2.5-VL](https://arxiv.org/abs/2502.13923)、[Qwen3-VL](https://arxiv.org/abs/2511.21631)、[InternVL3.5](https://arxiv.org/abs/2508.18265)。

这些路线没有统一的“最优连接器”。架构效果依赖视觉输入、主干能力、训练数据与计算预算的配合。相同 MLP 结构，也可能因为视觉分辨率和训练内容不同而表现差异很大。

另外，理解型 VLM 的文本输出路径并不自动支持图像生成。Chameleon、Janus-Pro 等统一理解与生成模型，还涉及视觉输出表示及相应训练，这是另一组架构取舍。[Chameleon](https://arxiv.org/abs/2405.09818)、[Janus-Pro](https://arxiv.org/abs/2501.17811)

## 六、主流训练阶段分别解决什么问题

### 6.1 先区分四种常被混称为“训练”的工作

| 工作 | 核心问题 | 典型学习内容 |
|---|---|---|
| 模块预训练 | 视觉与语言各自有什么基础能力？ | 图像表示、语言规律与文本生成 |
| 多模态对齐与继续预训练 | 这些模块怎样共同处理图文？ | 适配视觉输入，学习跨模态联系 |
| 视觉指令微调 SFT | 怎样按照用户任务回答？ | 选择证据、遵循指令、控制输出形式 |
| 偏好与反馈优化 | 怎样在候选行为中作出更好选择？ | 事实性、质量、可核验任务表现 |

同样叫 Pretrain 的脚本，可能只训练连接器，也可能训练整个多模态系统。名称相同，不代表目标、成本或更新范围相同。

### 6.2 模块预训练：获得可以复用的基础

视觉模块可以先通过图文匹配或视觉自监督训练学习表示，语言模块通过大量文本学习预测与表达。构建 VLM 时，经常直接使用这些已有权重。

```text
大量图片或图文数据 → 视觉模块的预训练权重 ─┐
                                          ├→ 组装 VLM
大量文本数据 ─────→ 语言模型的预训练权重 ─┘
```

图文表征学习与生成式对齐也应区分：CLIP、SigLIP 主要学习图文是否匹配；后面训练连接器时，可以通过“根据图片生成描述”建立适配，并不一定再使用相同的图文匹配目标。[CLIP](https://arxiv.org/abs/2103.00020)、[SigLIP](https://arxiv.org/abs/2303.15343)

选择语言 Base 还是 Instruct 也会影响后续工作。Base 的主要能力是语言续写，Instruct 已接受过指令训练。接入视觉后，仍需要检查它是否能够正确处理视觉任务及问答格式。

### 6.3 图文对齐：先建立可用的接口

典型做法是使用图片与描述文本，要求模型根据图片生成相关内容。对于随机初始化的连接器，常先冻结视觉和语言主干，只更新连接器。

```text
图片 → 视觉编码器〔冻结〕→ 连接器〔训练〕→ LLM〔冻结〕
                                                      ↓
                                                预测描述内容
                                                      ↓
                                                与参考描述比较
                                                      ↓
                                                调整连接器
```

这一阶段的目的是让视觉信息开始对语言输出产生有效影响，减少两个独立模块之间的不匹配。它不等于重新训练一个视觉编码器，也不等于已经获得通用看图聊天能力。

对齐并不一定要求视觉向量与某个词向量完全相等。通过图片条件下的文本预测，训练可以间接找到语言模型能够使用的视觉表达。

**冻结为什么仍能学习？** 冻结表示主干参数不更新，但主干仍参与计算。答案误差需要经过语言模型传回连接器，告诉它怎样调整输入。如果这条反馈路径被截断，连接器就无法从最终答案中学习。[PyTorch 自动求导说明](https://docs.pytorch.org/docs/2.14/notes/autograd.html#locally-disabling-gradient-computation)

### 6.4 多模态继续预训练：扩大协作能力

连接器适配之后，如果希望处理文档、图表、复杂空间关系、多图或视频，通常需要更广泛的训练数据，并考虑扩大可训练模块范围。

```text
图片描述 + 图文文档 + OCR + 图表 + 视频 + 纯文本等数据
                              ↓
                     多模态继续预训练
                              ↓
          按方案更新连接器、语言模型，必要时也更新视觉模块
```

这里强调的“联合”，是相关模块在同一个多模态任务目标下共同适应。具体是否解冻视觉编码器，要看原有视觉特征是否足够、数据量和计算预算。

混入纯文本数据可以帮助保持语言侧能力；增加高清或长输入训练，则让模型适应新的视觉与上下文条件。但数据比例、输入长度和冻结策略都需要实验，不能直接复制其他模型的配方。

Qwen3-VL 的公开训练包含连接器预热及后续全参数阶段；InternVL3.5 也报告了广泛的图文联合预训练。现代 VLM 并不都停留在仅训练连接器的阶段。[Qwen3-VL](https://arxiv.org/abs/2511.21631)、[InternVL3.5](https://arxiv.org/abs/2508.18265)

### 6.5 视觉 SFT：把图文能力转化为任务行为

图片描述回答的是“这张图里有什么”。视觉 SFT 则进一步要求模型理解当前指令，例如读取指定字段、比较两张图、只输出数字，或说明证据不足。

| 训练样本形式 | 模型重点学习什么 |
|---|---|
| 图片 + 概括性描述 | 组织整体内容 |
| 图片 + 具体问题 + 答案 | 根据问题选择视觉证据 |
| 文档 + 字段提取要求 + 结构化结果 | 读取文字并遵循输出格式 |
| 多张图 + 比较问题 + 答案 | 保持图片归属并联系差异 |
| 图片 + 无法判断的问题 + 恰当回应 | 区分可见信息和无依据推测 |

SFT 常见的监督范围是助手回答：图片与问题供模型读取，理想回答用于评价预测。**不对图片位置计算答案损失，仍然要让模型能够读取这些位置。**

对齐训练与 SFT 可以使用相似的文本生成目标，差异主要在数据内容、任务形式和参数更新范围，而不是必须更换一套完全不同的算法。

### 6.6 偏好优化与强化学习：利用比较或结果继续改进

当基本图文能力与任务行为已经建立后，可以利用反馈调整回答。

```text
同一张图 + 同一个问题
          ↓
      生成候选回答
          ↓
比较哪个更好，或检查任务结果是否正确
          ↓
提高更可靠行为的概率
```

- **偏好优化**：使用较好与较差回答的比较，DPO 是一种常见方法。
- **强化学习**：对模型采样的回答计算奖励，再据此调整策略，PPO、GRPO 是可用的优化方法。
- **人工或 AI 反馈**：说明反馈来源，常见称呼为 RLHF、RLAIF；它们与优化算法不在同一层级。

来源：[DPO](https://arxiv.org/abs/2305.18290)、[DeepSeekMath / GRPO](https://arxiv.org/abs/2402.03300)、[RLAIF-V](https://arxiv.org/abs/2405.17220)。

视觉反馈要真正核验图像。只奖励流畅、详细的措辞，可能使模型更会表达，却更容易编造。可核验任务可使用读取结果、计算结果或定位结果；开放式描述则需要更可靠的评价与筛选。

这类训练不是所有 VLM 的必经阶段，也不能替代基础感知与图文对齐。

## 七、业界常见的训练方案怎样组合

上一节解释了训练目标，这一节说明它们怎样组成实际方案。不能把所有模型都归纳成同一条固定流水线。

### 7.1 方案一：先对齐，再做视觉指令微调

```text
已有视觉编码器 + 已有语言模型 + 新连接器
                       ↓
第一阶段：用图文描述适配连接器
                       ↓
第二阶段：用视觉指令数据训练任务行为
                       ↓
              评估并继续针对性改进
```

经典 LLaVA 路线采用这样的分阶段思路：对齐时重点训练投影模块，指令训练时进一步更新语言侧，视觉主干保持冻结。它结构直接，阶段目标明确，适合理解生成式 VLM 的基本训练逻辑。[LLaVA](https://arxiv.org/abs/2304.08485)

这种方案复用两个成熟主干的能力。其上限仍取决于视觉表示、语言基座和指令数据，不能仅凭完成两阶段就认定复杂任务已经学会。

### 7.2 方案二：冻结主干，训练更有能力的桥接模块

这类方案把适配能力更多放在新增模块中。主干可以继续冻结，桥接模块本身承担更复杂的信息提取与交互。

BLIP-2 先训练 Q-Former 学习与文本有关的视觉表示，再把它接入冻结 LLM 进行生成式适配。其前一部分不只是普通 caption 训练，还包含图文匹配等学习任务。[BLIP-2](https://arxiv.org/abs/2301.12597)

Flamingo 则训练视觉重采样器和新增的跨注意力模块，保持原有视觉、语言主干冻结。它的“只训练新增部分”比“只训练两层 MLP”包含更多结构。[Flamingo](https://arxiv.org/abs/2204.14198)

因此，看到“主干冻结”时，还要继续看究竟训练了哪些新增模块。

### 7.3 方案三：联合多模态训练，再进行后训练

```text
初始化视觉与语言模块
          ↓
可选的连接器预热
          ↓
大规模多模态继续预训练
          ↓
视觉指令 SFT
          ↓
可选的偏好优化、蒸馏或强化学习
```

这类方案往往希望覆盖更广泛任务，会同时设计视觉输入、数据混合、长上下文和参数更新范围。Qwen3-VL、InternVL3.5 的公开配方体现了这种更广泛的训练思路，但阶段划分与细节并不完全相同。[Qwen3-VL](https://arxiv.org/abs/2511.21631)、[InternVL3.5](https://arxiv.org/abs/2508.18265)

它提供更多适应自由度，也需要更充分的数据、计算和能力回归评估。“全参数训练”不是质量保证，只是允许模型作出更广泛的改变。

### 7.4 LoRA、局部解冻属于更新方式，可以用于不同方案

| 更新方式 | 更新哪里 | 主要特点 |
|---|---|---|
| 只训连接器 | 跨模态接口 | 新增参数少，适配范围有限 |
| 局部解冻 | 连接器与部分主干层 | 在资源与适应能力之间折中 |
| LoRA | 指定层中的低秩适配参数 | 减少需要更新的参数 |
| 全参数微调 | 指定主干的全部参数 | 自由度较大，资源与数据要求更高 |

LoRA 不是与 SFT 并列的训练阶段。一个模型可以“使用 LoRA 做视觉 SFT”，也可以在其他阶段使用适配器。QLoRA 还结合低比特主干存储，减少相关内存开销，但不会消除视觉输入和长序列的全部成本。[LoRA](https://arxiv.org/abs/2106.09685)、[QLoRA](https://arxiv.org/abs/2305.14314)

同样，教师模型生成训练答案、筛选合成数据或提供反馈，可以进入多个阶段。合成内容仍需核验图像事实，教师也可能产生视觉错误。

### 7.5 比较方案时，至少看四项

| 比较项 | 要问的问题 |
|---|---|
| 初始化 | 视觉和语言主干已经具备什么能力？ |
| 更新范围 | 只训接口、部分解冻，还是联合训练？ |
| 数据与目标 | 学习描述、具体问答、长图文还是反馈偏好？ |
| 输入与评估 | 分辨率、视觉位置、多图形式是否匹配目标任务？ |

这样就能把“网络长什么样”“正在训练什么能力”“允许哪些参数变化”分开理解，避免被单个模型名称或脚本名称误导。

## 八、数据与评估怎样支撑训练

### 8.1 数据质量影响整个信息链路

一条图片可以对应多条问答，因此样本行数不等于独立图片数量。训练数据还需要关注任务种类、语言分布、图片清晰度，以及答案能否从图中得到支持。

大量粗略描述不能替代细节读取训练。图片缩放后已经看不清的文字，也不适合继续当作“模型应当准确读出”的监督。数据与输入处理必须一起检查。

### 8.2 学会训练答案，不等于可靠回答新问题

训练时，模型通常可以利用参考答案中已经给出的前文，练习预测后续内容。实际使用时没有参考答案，需要根据自己的已生成内容继续回答。因此，训练误差降低后仍然要检查自由生成结果。

验证数据还应避免与训练数据共享相同或高度相似的图片。文档和视频需要按来源分组，防止验证只是再次遇到熟悉内容。

### 8.3 用视觉对照检查是否真正利用图像

```text
固定问题：“牛肉面多少钱？”

菜单 A 标价 39 元 → 理想回答：39 元
菜单 B 标价 49 元 → 理想回答：49 元
菜单 C 价格模糊  → 理想回答：无法确定
```

这是评估思路示例，不是某个模型的实测。关键是答案是否随视觉证据合理改变。

正确图与错配图下的预测误差比较，也可以诊断视觉输入是否产生作用；但其差值不是问答准确率，也不能单独证明细粒度理解能力。

### 8.4 根据错误定位瓶颈

| 现象 | 优先检查的环节 |
|---|---|
| 能识别大类，读不清小字 | 分辨率、视觉特征与 OCR 数据 |
| 内容读对，但关联到错误对象 | 空间关系、问题理解与任务监督 |
| 换图后答案几乎不变 | 图像接入、对齐与语言先验依赖 |
| 无依据的问题也肯定回答 | 数据标签、指令训练与反馈标准 |
| 单图正常，多图混淆 | 图片归属与多图训练 |
| 新任务提升，原有能力下降 | 更新范围、数据混合与遗忘 |

架构提供信息通路，训练建立使用这条通路的能力，评估检验它是否在新输入上可靠。三者需要一起分析。

## 十、本项目采用的架构

miniLLM-vlm 采用输入层融合，使用已有视觉与语言权重，只训练连接器完成当前的 Pretrain 对齐。

```text
图片：256 × 256
      ↓
SigLIP2 视觉编码器〔冻结〕
      ↓
64 个视觉位置，每个位置宽度 768
      ↓
LayerNorm → Linear → GELU → Linear〔可训练〕
      ↓
替换输入序列中的 64 个图像占位嵌入
      +
问题的文本嵌入
      ↓
miniLLM Base〔冻结〕
      ↓
生成文本答案；训练反馈传回连接器
```

| 部分 | 当前选择 |
|---|---|
| 视觉模块 | SigLIP2 固定分辨率视觉权重的兼容导出；32×32 patch 形成 8×8 网格 |
| 连接器 | 带归一化的两层 MLP，约 118 万可训练参数；保持 64 个视觉位置 |
| 语言模块 | miniLLM Base；已有运行摘要为 8 层、宽度 768、4 个专家的 MoE |
| 图像接入 | 使用已有占位 token，替换嵌入，词表不扩充 |
| 当前训练 | 冻结两端，只训练连接器；以助手答案预测建立适配，并保留 Base 的 MoE 辅助项 |
