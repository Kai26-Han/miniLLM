# 大模型主流自注意力架构解析：从 QKV 到 GQA、MLA 与高效推理

> 本文围绕业界 Attention 的共同原理和主要演进路线展开；miniLLM 的实现只在文末作为最小案例出现。

## 1. Attention 到底解决什么

自注意力让每个 Token 根据当前任务，从上下文中动态读取信息。卷积的连接模式由位置预先决定，Attention 的连接权重则由内容计算。

对位置 \(i\) 而言，可以把它理解成一次可微检索：

1. Query 表示“当前位置想找什么”；
2. Key 表示“每个历史位置能用什么方式被匹配”；
3. Value 表示“匹配后实际取回什么信息”。

## 2. Scaled Dot-Product Attention

输入隐藏状态 \(X\in\mathbb{R}^{B\times S\times d}\)，线性投影得到：

\[
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
\]

单个头的输出为：

\[
\operatorname{Attention}(Q,K,V)=
\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}+M\right)V
\]

其中 \(d_h\) 是头维度，\(M\) 是 Mask。

### 2.1 为什么除以 \(\sqrt{d_h}\)

若 Q、K 各维近似独立且方差相近，点积方差会随 \(d_h\) 增长。缩放可以避免 logits 过大、Softmax 过度饱和和梯度变差。

### 2.2 Softmax 做了什么

Softmax 将每个 Query 对允许 Key 的分数变成非负且和为 1 的权重，再对 Value 做加权和。注意力权重可以辅助诊断，但不能直接等同为完整的因果解释。

## 3. 因果 Mask、Padding Mask 与文档 Mask

### 3.1 Causal Mask

Decoder-only 不能读取未来 Token：

\[
M_{ij}=\begin{cases}
0,&j\le i\\
-\infty,&j>i
\end{cases}
\]

这是自回归训练不泄漏答案的前提。

### 3.2 Padding Mask

不同长度样本组成 Batch 时，Padding 位置不能作为有效 Key/Value。Loss Mask 只是不计算 Padding 标签的损失，不能替代 Attention Mask。

### 3.3 Packed Sequence 的边界 Mask

为提高 Token 利用率，工业训练常把多个文档拼到同一序列。此时需要 Block-diagonal 或文档边界感知 Mask，避免后一个文档无意读取前一个无关文档；是否允许跨文档注意，需要与训练配方一致。

## 4. Multi-Head Attention 为什么有效

将隐藏维度拆成多个头：

\[
\operatorname{MHA}(X)=\operatorname{Concat}(head_1,\ldots,head_H)W_O
\]

不同头可以学习不同的关系子空间，例如局部搭配、指代、代码结构或长距离依赖。头数更多不必然更好，因为头维度、冗余、训练规模和硬件形状共同决定效果。

## 5. MHA、MQA、GQA 和 MLA

### 5.1 MHA：完整的 K/V 头

Query、Key、Value 都有 \(H\) 个头。表达自由度高，但每层每个历史 Token 要缓存 \(2Hd_h\) 个 K/V 元素。

### 5.2 MQA：共享一组 K/V

所有 Query 头共享一个 Key 头和一个 Value 头。KV Cache 大幅下降，适合强调解码效率的模型，但压缩过强时可能损失质量。

### 5.3 GQA：分组共享 K/V

保留 \(H_q\) 个 Query 头，只使用较少的 \(H_{kv}\) 个 K/V 头，每组 Query 共享一组 K/V：

\[
\text{group size}=H_q/H_{kv}
\]

GQA 是现代 Decoder-only 的常见折中，Llama 2 70B、Llama 3、Mistral 和 Gemma 新版本等公开模型均采用过这一路线。

### 5.4 MLA：缓存低维潜在变量

MLA 不只是减少 K/V 头，而是把 K/V 表示压缩到低维潜在空间，再为各头恢复需要的内容。其目标是进一步降低 KV Cache，同时保留多头表达。DeepSeek-V2/V3 是代表性公开实现。

| 结构 | KV 表示 | Cache 大小 | 工程特点 |
|---|---|---:|---|
| MHA | 每个 Q 头独立 K/V | 最大 | 简单、表达充分 |
| GQA | 一组 Q 头共享 K/V | 中等 | 质量与效率平衡 |
| MQA | 全部 Q 头共享 K/V | 小 | Decode 友好、压缩激进 |
| MLA | 缓存低维潜在表示 | 很小 | 结构和内核更复杂 |

## 6. 位置如何进入 Attention

### 6.1 绝对位置 Embedding

把位置向量加到 Token Embedding，直观但对超出训练长度的外推较弱。

### 6.2 相对位置 Bias

根据 Query 与 Key 的相对距离给分数加 Bias。T5、ALiBi 等路线属于这一大类。

### 6.3 RoPE

RoPE 对 Q/K 的成对维度施加位置相关旋转。旋转后的点积依赖相对位置，因此适合 Decoder-only，也便于与 KV Cache 结合。

RoPE 长度扩展常见手段包括频率缩放、NTK-aware Scaling、YaRN 和长上下文继续训练。无论采用哪种方法，都要在 Needle Retrieval、多跳检索、长文理解和长输出上分别验证。

## 7. 全局、局部、稀疏与混合 Attention

### 7.1 Full Attention

每个位置可关注全部历史，训练分数矩阵规模为 \(O(S^2)\)。它语义灵活，但长序列成本高。

### 7.2 Sliding-window Attention

每个位置只关注最近 \(W\) 个 Token，复杂度约为 \(O(SW)\)。适合局部依赖强的文本，但单层无法直接连接很远的位置。

### 7.3 局部/全局层交错

多层局部 Attention 会逐层扩大感受野，少量全局层再建立远距离通路。Mistral、Gemma 2/3 的公开设计展示了这类思路。

### 7.4 Block-sparse 与结构化稀疏

按窗口、块、全局 Token 或任务结构选择连接，能降低理论计算，但只有匹配的稀疏内核和硬件布局才能转化成真实加速。

## 8. QK-Norm、Soft Capping 与注意力稳定性

模型规模和上下文增大后，Attention logits 可能异常放大。常见控制方式包括：

- 在 Query/Key 上应用 RMSNorm 或 LayerNorm；
- 对 logits 做 Soft Capping；
- 调整初始化、学习率和数值精度；
- 监控每层注意力熵和 logits 极值。

Gemma 3 的公开说明展示了从 Soft Capping 转向 QK-Norm 的具体架构选择。它说明稳定性机制也是可消融的设计，而非固定模板。

## 9. FlashAttention：精确 Attention 的 IO 优化

朴素实现会显式物化 \(S\times S\) 分数矩阵，造成大量显存读写。FlashAttention 通过分块、在线 Softmax 和 Kernel 融合，减少 HBM 往返。

关键结论：

- 它计算的是精确 Attention，而不是近似稀疏 Attention；
- 渐近计算复杂度仍是 \(O(S^2)\)；
- 真正减少的是中间张量物化和 IO；
- 是否走到最快 Kernel 取决于 dtype、头维度、Mask 形状和硬件。

PyTorch SDPA 是统一接口，运行时可选择 Flash、Memory-efficient 或 Math Backend。使用接口不代表任何输入都自动命中最快路径。

## 10. KV Cache 与 Decode

自回归生成第 \(t\) 个 Token 时，历史 Token 的 K/V 不会改变，因此可缓存并只计算新 Token 的 Q/K/V。

单样本缓存元素量近似为：

\[
N_{KV}=2\cdot L\cdot S\cdot H_{kv}\cdot d_h
\]

这解释了为什么 GQA、MQA、MLA 和 KV 量化对长上下文服务如此重要。

### 10.1 Paged Attention 与 Continuous Batching

分页管理 KV Cache 可减少不同长度请求造成的显存碎片。Continuous Batching 在请求生成过程中动态加入和移出序列，提高服务吞吐。

### 10.2 Prefill 与 Decode 的瓶颈不同

- Prefill 同时处理大量 Token，通常更偏计算密集；
- Decode 每步只处理少量新 Token，通常更偏权重和 KV 的内存带宽密集。

因此同一个 Attention 结构在训练、Prefill 和 Decode 阶段的收益可能不同。

## 11. Attention 的成本怎么估算

忽略常数时：

- QKV/O 投影计算约为 \(O(Sd^2)\)；
- Full Attention 的 QK 和 AV 约为 \(O(S^2d)\)；
- Attention 分数中间量约为 \(O(HS^2)\)；
- Decode 的 KV Cache 随 \(L\)、\(S\)、\(H_{kv}\)、\(d_h\) 线性增长。

短序列、大隐藏维度时，投影层可能占主导；超长序列时，二次项会越来越重要。只背“Attention 是平方复杂度”不足以判断真实瓶颈。

## 12. 如何验证 Attention 实现

一个可靠实现至少需要：

1. **形状测试**：不同 Batch、长度、头数和 KV 头组合输出正确。
2. **因果泄漏测试**：改变未来 Token 不影响更早位置输出。
3. **Padding 不变性**：增加右侧 Padding 不改变有效位置结果。
4. **朴素公式对照**：小张量上与手写 Softmax Attention 对齐。
5. **GQA 等价测试**：显式复制 K/V 与分组实现一致。
6. **RoPE 测试**：位置、广播、dtype 和缓存增量一致。
7. **全量/增量一致性**：启用 KV Cache 后逐步 Decode 与整段前向一致。
8. **性能测试**：分别测 Prefill 吞吐、Decode 延迟、显存和 Kernel 命中。

## 13. 主流 Attention 的选择逻辑

| 目标 | 常见选择 | 主要风险 |
|---|---|---|
| 训练基线与最高兼容性 | MHA/GQA + Full Attention | 长上下文成本 |
| 降低 Decode KV Cache | GQA、MQA、MLA | 质量与实现复杂度 |
| 降低长序列训练成本 | Sliding-window、Hybrid、Sparse | 远距离信息传播 |
| 提升精确 Attention 内核效率 | FlashAttention/SDPA | 输入条件影响 Kernel |
| 超长上下文外推 | RoPE Scaling + 继续训练 | 标称长度不等于有效能力 |
| 端到端服务吞吐 | KV Cache + Paging + Continuous Batching | 调度和显存管理复杂 |

## 14. miniLLM 的 Attention 映射

miniLLM 使用 8 个 Query 头、4 个 KV 头的 GQA，先对 Q/K 应用 RoPE，再显式扩展 K/V 并调用 PyTorch SDPA。无 Padding 时使用 `is_causal=True`；存在 Padding 时组合因果 Mask 与 Key Padding Mask。

这套实现覆盖了现代 Decoder Attention 的核心教学路径，但还不是完整推理架构：当前没有 KV Cache、Paged Attention、局部/全局层混合和 QK-Norm；每层 Padding 分支还会构造因果矩阵。下一步最有价值的是先补因果泄漏、Padding 不变性和朴素公式对照测试，再实现 KV Cache 并验证全量/增量一致性。
