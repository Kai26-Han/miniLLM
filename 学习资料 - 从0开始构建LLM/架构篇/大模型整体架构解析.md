# 大模型主流整体架构解析：从 Transformer 主干到多模态与推理系统

> 本文的核心是业界主流大模型架构。miniLLM 仅在文末作为一个可运行的教学映射，用来说明这些设计如何落到代码。

## 1. 先分清“大模型架构”的四个层级

讨论大模型架构时，常把不同层级混在一起。更准确的拆法是：

1. **序列建模范式**：Encoder-only、Decoder-only、Encoder–Decoder，以及 Attention–SSM 混合架构。
2. **Transformer Block**：Attention、FFN/MoE、归一化、残差与位置编码怎样组合。
3. **模型系统**：文本、视觉、音频、工具等模态如何进入同一模型，训练和推理如何并行。
4. **服务系统**：Prefill、Decode、KV Cache、连续批处理、量化和分布式推理。

因此，“用了 MoE”不能完整描述一个模型；它只说明 FFN 子层采用稀疏专家，而没有说明 Attention、位置编码、多模态和服务架构。

## 2. 三种经典 Transformer 范式

### 2.1 Encoder-only：擅长理解与表示

Encoder 中每个 Token 通常可以双向关注整段输入，输出上下文化表示。BERT 一类模型适合分类、检索、实体识别和向量表示。

它的优势是输入理解充分，局限是不能天然按自回归方式连续生成长文本。

### 2.2 Decoder-only：当前通用生成模型的主干

Decoder-only 使用因果掩码，第 \(t\) 个位置只能看到不晚于 \(t\) 的 Token：

\[
p(x_{1:T})=\prod_{t=1}^{T}p(x_t\mid x_{<t})
\]

同一目标可以统一文本补全、对话、代码、结构化输出和工具调用。Llama、Mistral、Gemma、Qwen、DeepSeek 等公开模型家族都证明了这条路线的可扩展性。

### 2.3 Encoder–Decoder：输入理解与输出生成分工

Encoder 双向读取输入，Decoder 通过 Cross-Attention 条件生成输出。T5、BART 和原始 Transformer 属于这一范式，在翻译、摘要、语音识别等输入输出边界明确的任务中仍有价值。

| 范式 | 注意力可见性 | 典型目标 | 主要场景 |
|---|---|---|---|
| Encoder-only | 输入内双向 | MLM、对比学习 | 表示、检索、分类 |
| Decoder-only | 因果单向 | Next-token Prediction | 通用生成、对话、代码、Agent |
| Encoder–Decoder | Encoder 双向，Decoder 因果 | Denoising、Seq2Seq | 翻译、摘要、跨模态生成 |

## 3. 现代 Decoder-only 的公共骨架

现代文本大模型虽有大量细节差异，主干高度相似：

```text
Token IDs
  -> Token Embedding
  -> N × Decoder Block
       -> Norm -> Causal Self-Attention -> Residual
       -> Norm -> Dense FFN / Sparse MoE -> Residual
  -> Final Norm
  -> LM Head
  -> Next-token logits
```

这套架构成为主流，不是因为它在每个维度都理论最优，而是因为它同时具备：统一训练目标、规则的矩阵计算、成熟的并行方案、稳定的扩展规律和完善的软硬件生态。

## 4. 输入层：Tokenizer、Embedding 与输出头

Tokenizer 把文本或结构标记转换为离散 ID，Embedding 将 ID 映射为 \(d_{model}\) 维向量。词表设计会同时影响：

- 多语言和代码的压缩率；
- Embedding/LM Head 参数量；
- 序列长度与 Attention 成本；
- 特殊标记、工具调用和 Chat Template 的稳定性。

LM Head 将隐藏状态投影回词表空间。输入 Embedding 与输出头可以共享权重（weight tying），以减少参数并增强输入输出表示的一致性；超大模型也可能基于训练或部署目标选择不共享。

## 5. 位置编码：RoPE 已成主流，但不是长上下文的全部

绝对位置 Embedding 在早期模型中常见，现代 Decoder-only 更常使用 RoPE。RoPE 把位置相关旋转作用到 Query 和 Key，使点积自然包含相对位置信息。

设一对二维分量为 \((x_1,x_2)\)，位置 \(m\) 对应角度 \(m\theta\)，则旋转为：

\[
\begin{bmatrix}x'_1\\x'_2\end{bmatrix}
=
\begin{bmatrix}
\cos(m\theta)&-\sin(m\theta)\\
\sin(m\theta)&\cos(m\theta)
\end{bmatrix}
\begin{bmatrix}x_1\\x_2\end{bmatrix}
\]

长上下文通常还需要位置缩放、长序列继续训练、匹配的数据分布和检索能力评测。把配置中的最大位置从 8K 改成 128K，并不等于模型真正获得了 128K 的有效上下文能力。

## 6. Attention：从 MHA 到 GQA、MLA 与局部注意力

### 6.1 MHA、MQA 与 GQA

- **MHA**：每个 Query 头都有独立 K/V 头，表达力强，但 KV Cache 大。
- **MQA**：所有 Query 头共享一组 K/V，显著减少 KV Cache，压缩较激进。
- **GQA**：若干 Query 头共享一个 K/V 头，在质量与推理成本间取得平衡，已成为常见方案。

若层数为 \(L\)、上下文长度为 \(S\)、KV 头数为 \(H_{kv}\)、头维度为 \(D_h\)，单样本 KV Cache 元素量近似为：

\[
2LSH_{kv}D_h
\]

这说明降低 KV 头数会直接降低长上下文解码显存。

### 6.2 MLA：压缩 KV 表示

Multi-head Latent Attention 将 K/V 压缩到低维潜在表示，并在使用时重建相关分量。它与 GQA 的目标相似，都是降低推理缓存和带宽，但结构与工程实现不同。DeepSeek-V2/V3 是其代表性公开实践。

### 6.3 Full、Sliding-window 与 Hybrid Attention

全局 Attention 能连接任意历史位置，但训练计算随序列长度近似二次增长。滑动窗口 Attention 只关注最近 \(W\) 个 Token，复杂度从 \(O(S^2)\) 降至约 \(O(SW)\)。

实际模型常交错局部层和全局层：局部层控制成本，全局层负责远距离信息传播。Mistral 使用滑动窗口；Gemma 2/3 展示了局部与全局层交错的公开路线。

## 7. FFN：SwiGLU 与参数主体

Attention 负责 Token 间的信息混合，FFN 负责每个 Token 内部的通道变换。现代模型常用 SwiGLU：

\[
\operatorname{SwiGLU}(x)=W_o\big(\operatorname{SiLU}(W_gx)\odot W_ux\big)
\]

FFN 通常占据 Transformer 的大部分参数，因此“Dense 还是 MoE”主要是 FFN 子层的选择。

### 7.1 Dense FFN

每个 Token 都经过相同参数。优点是训练简单、通信少、延迟稳定；缺点是增加参数通常也会同步增加每 Token 计算量。

### 7.2 Sparse MoE

Router 为每个 Token 选择少量 Expert：

\[
y=\sum_{i\in\operatorname{TopK}(r(x))}g_i(x)E_i(x)
\]

MoE 可以让总参数量远大于单 Token 激活参数量，但会引入负载均衡、容量控制、All-to-All 通信和部署显存问题。现代实现还常加入 Shared Expert，让通用知识始终经过共享路径。

## 8. 归一化、残差与 Block 组织

### 8.1 Pre-Norm 与 Post-Norm

Pre-Norm 在子层前归一化：

\[
h'=h+F(\operatorname{Norm}(h))
\]

它通常更利于深层网络稳定训练。Post-Norm 在残差相加后归一化，部分新模型通过额外技巧重新采用或组合两者。行业没有永恒唯一答案，但稳定性必须通过规模化实验验证。

### 8.2 RMSNorm

RMSNorm 只根据均方根缩放，不减均值：

\[
\operatorname{RMSNorm}(x)=g\odot\frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2+\epsilon}}
\]

它计算简单，已广泛用于 Decoder-only 模型。QK-Norm 则在 Query/Key 上额外归一化，用于控制注意力 logits 的尺度。

## 9. Transformer 之外：SSM 与混合架构

State Space Model 通过递推状态处理序列，理论上可以线性扩展长度，并避免完整 KV Cache。Mamba 是代表性路线。纯 SSM 在内容寻址和生态成熟度上与 Attention 有不同取舍，因此更常见的工程方向之一是 Attention–SSM 混合：

- SSM/线性递推层负责大部分长序列传播；
- 少量 Attention 层承担精确检索和全局交互；
- 卷积或门控模块补充局部建模。

这条路线很重要，但通用大模型的默认基线目前仍是 Transformer 或以 Transformer 为核心的混合结构。

## 10. 多模态架构：接入式与原生融合

多模态模型通常包含三个部分：模态编码器、连接模块和语言模型主干。

### 10.1 模块化接入

视觉编码器先输出视觉特征，再经 Projector 或 Cross-Attention 接入 LLM。这种方式易于复用成熟模型、训练成本较低。

### 10.2 早期融合与统一 Token 流

文本、图像或视频表示较早进入统一主干进行联合预训练。Llama 4 的公开介绍将其称为原生多模态早期融合。优势是跨模态交互更深，代价是数据、训练稳定性和系统复杂度更高。

多模态“统一”通常是表示和主干统一，并不意味着原始像素、音频波形和文本字符使用完全相同的前端编码算法。

## 11. 推理架构也是模型架构的一部分

### 11.1 Prefill 与 Decode

- **Prefill**：并行处理完整输入，计算密集。
- **Decode**：逐 Token 生成，访存和 KV Cache 带宽常成为瓶颈。

### 11.2 KV Cache 与 Paged Attention

KV Cache 避免每次 Decode 重算历史 K/V。Paged Attention 以分页方式管理不同长度请求的缓存，降低碎片，并支持连续批处理。

### 11.3 量化、并行与推测解码

- 权重/激活/KV 量化降低显存和带宽；
- Tensor、Pipeline、Expert、Sequence Parallel 解决单设备容量限制；
- 推测解码用小模型提出候选、大模型并行验证，在不改变目标分布的前提下降低串行步数。

所以，模型参数量相同不代表线上成本相同；KV 结构、上下文长度、批处理策略和硬件内核同样关键。

## 12. 公开模型架构的代表性组合

下面的表格用于理解“设计组合”，不用于简单排名。

| 公开模型路线 | 代表性结构 | 主要目标 |
|---|---|---|
| Llama 3 | Decoder-only、Dense、GQA、RoPE、SwiGLU | 稳定扩展与开放生态 |
| Mistral 7B | Decoder-only、GQA、Sliding-window Attention | 控制长序列推理成本 |
| DeepSeek-V3 | Decoder-only、MLA、细粒度 MoE、Shared Expert、MTP | 提高参数容量与训练/推理效率 |
| Gemma 3 | GQA、局部/全局 Attention 交错、QK-Norm、多模态 | 长上下文和端侧/多尺寸部署 |
| Llama 4 | 原生多模态、MoE、共享与路由专家 | 大容量、低激活、多模态融合 |
| Mamba 系列 | Selective SSM 或 Attention–SSM 混合 | 线性序列建模与低缓存 |

## 13. 如何做架构选择

架构选择应从瓶颈反推：

| 目标或瓶颈 | 优先考虑 | 需要验证 |
|---|---|---|
| 单卡、小模型、低延迟 | Dense + GQA | Dense 基线是否已充分训练 |
| 总参数容量受限于计算 | Sparse MoE | 路由均衡、通信、显存 |
| 长上下文 Decode 显存高 | GQA/MQA/MLA、局部 Attention | 长上下文有效性而非只测可运行 |
| 超长序列训练过贵 | 局部/稀疏 Attention、混合 SSM | 远距离检索和全局推理 |
| 多模态快速落地 | 编码器 + Projector + LLM | 模态对齐和输入长度 |
| 原生跨模态能力 | 早期融合联合预训练 | 数据规模、训练稳定性、成本 |

正确的架构决策必须同时报告质量、训练吞吐、峰值显存、首 Token 延迟、单 Token 延迟和部署复杂度。

## 14. miniLLM：把主流组件缩成一个教学模型

miniLLM 当前实现是一个紧凑的 Decoder-only Causal LM：8 层、隐藏维度 768、8 个 Query 头和 4 个 KV 头；使用 RoPE、RMSNorm、GQA、SwiGLU，并支持 Dense 与 4 Expert/Top-1 Sparse MoE 切换。输入输出 Embedding 默认共享权重，训练目标是 Next-token Cross-Entropy。

它与主流架构的对应关系很直接：

```text
业界 Decoder-only 主干  -> MiniLLMForCausalLM
RMSNorm + Pre-Norm       -> MiniLLMRMSNorm / MiniLLMDecoderLayer
GQA + RoPE + SDPA        -> MiniLLMAttention
SwiGLU Dense FFN         -> MiniLLMMLP
Top-1 Sparse MoE         -> MiniLLMSparseMoE
```

miniLLM 的定位是“可读、可训练、可做消融”，不是生产级缩微复制。它尚未实现 KV Cache、Paged Attention、Expert Parallel、Shared Expert 和局部/全局混合 Attention；配置支持 32768 位置也不等于已经通过长上下文训练与评测。最有价值的使用方式，是以 Dense 为基线，逐项比较 GQA、MoE、序列长度和推理缓存带来的质量—成本变化。
