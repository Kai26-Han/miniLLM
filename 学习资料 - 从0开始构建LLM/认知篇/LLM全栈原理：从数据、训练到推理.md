# LLM全栈原理：从数据、训练到推理模型

##  核心原理

大语言模型先把海量文本转换为 token，通过预测下一个 token 学习语言和世界规律；再通过监督微调学会以助手的方式响应，通过强化学习练习可验证任务并发现更有效的推理策略。它本质上仍是一个概率生成系统：能力广泛却不均匀，参数中的知识只是模糊记忆，可靠使用必须依靠上下文、工具、验证和人的监督。

## 关键点

1. **训练 LLM 的起点不是“智能”，而是经过清洗的海量数据。** 数据来源、语言比例、去重和质量过滤会直接塑造模型能力。
2. **模型不直接读取文字，而是读取 token。** 人眼看到的字符、单词和模型看到的符号边界并不相同。
3. **预训练只有一个核心目标：预测下一个 token。** 这个简单目标迫使模型压缩语言、事实和世界规律。
4. **基础模型是互联网文档模拟器，不是天然的聊天助手。** 它擅长续写“像互联网的文本”。
5. **监督微调通过对话样本编程模型。** 数据中的理想回答、行为准则和拒答方式，共同构成助手的“人格”。
6. **参数知识类似模糊的长期记忆，context window 类似工作记忆。** 需要精确处理的资料最好直接放进上下文。
7. **幻觉源于生成机制与训练数据。** 如果训练样本总是自信回答，模型在不知道时也会模仿这种形式进行猜测。
8. **模型需要 token 来思考。** 每生成一个 token 所能完成的计算有限，中间步骤相当于模型的草稿纸。
9. **LLM 的智能是“锯齿状”的。** 它可能解决高难度专业问题，却在数数、拼写或小数比较上出错。
10. **强化学习让模型从模仿专家走向自主练习。** 模型生成大量解法，验证结果，再提高成功路径的概率。
11. **可验证奖励和人类偏好奖励不是一回事。** 前者更难欺骗；后者依赖奖励模型，容易被优化过程钻空子。
12. **可靠的 LLM 应用不是“问一句、复制答案”，而是“给上下文、让它调用工具、检查结果、保留人工责任”。**

---

## 全栈流程概览

```text
原始互联网数据
      │
      ▼
抓取、文本提取、质量过滤、语言筛选、去重、隐私清理
      │
      ▼
Tokenizer：文本 → 一维 token 序列
      │
      ▼
预训练：预测下一个 token
      │
      ▼
基础模型：互联网文档模拟器
      │
      ▼
监督微调（SFT）：学习对话、指令遵循和行为规范
      │
      ▼
助手模型：能回答问题、拒绝请求、调用工具
      │
      ├── 偏好优化 / RLHF：更符合人类偏好
      │
      └── 可验证强化学习：练习数学、代码等任务
                     │
                     ▼
              推理 / 思考模型
```

## Part 1：预训练——知识从哪里来？

### 1. 原始数据必须经过系统处理

互联网抓取得到的不是干净知识库，而是充满 HTML、导航、广告、垃圾内容、重复页面和隐私信息的原始材料。典型数据管线包括：

1. **网页抓取**：从种子页面出发，沿链接持续索引互联网。
2. **URL 与域名过滤**：排除恶意、垃圾、成人、营销等低价值或高风险来源。
3. **正文提取**：从 HTML 中去掉导航、样式和页面模板，只保留有意义的文本。
4. **语言识别**：判断文档语言，并按目标能力调整不同语言的比例。
5. **质量过滤**：移除乱码、模板化内容、低信息密度页面和异常文本。
6. **去重**：删除重复文档与高度相似片段，避免模型反复学习少数内容。
7. **隐私清理**：尽可能识别并去除地址、身份号码等个人可识别信息。

模型最终学到什么，不仅取决于数据量，也取决于过滤标准。训练数据中的语言比例会影响多语言能力，来源偏差会进入模型，重复数据则可能放大记忆与过拟合。

### 2. 数据规模不等于磁盘体积

高质量文本经过激进过滤后，磁盘体积可能只有几十 TB，但转换后仍会形成数万亿 token 的训练序列。训练成本的核心不是“文件能不能放进硬盘”，而是这些 token 要经过多少次神经网络计算，以及模型有多少参数需要更新。

### 3. Tokenization：模型眼中的文字

神经网络需要有限符号集合构成的一维序列，因此自然语言必须先转换为 token。

最底层可以从二进制位或 UTF-8 字节开始，但这样序列太长。实际系统常使用类似 Byte Pair Encoding（BPE）的算法：

1. 从字节或基础符号开始；
2. 找出数据中经常连续出现的符号对；
3. 把高频组合合并为新 token；
4. 反复合并，直到达到目标词表大小。

这里存在一个基本权衡：

| 方案 | 词表大小 | 序列长度 | 特点 |
|---|---:|---:|---|
| 字节级 | 小 | 很长 | 通用，但计算成本高 |
| 子词级 | 中等 | 中等 | 当前常见折中方案 |
| 大词块 | 大 | 较短 | 词表和输出层更大，低频组合利用率低 |

Token 不是严格的单词：它可能是一个字符、词根、完整单词、空格加单词，甚至一段标点。大小写、前导空格和拼写变化都可能产生完全不同的 token 序列。

### 4. 为什么 token 如此重要？

Tokenization 不只是输入格式，它会改变模型的认知难度：

- 常见词可能只占一个 token，罕见词可能被拆成多个 token；
- 模型看到的是 token ID，不是人眼看到的字符；
- 不同语言的压缩效率可能不同，相同内容需要的 token 数也不同；
- 字符级拼写、逐字计数和字符串处理对模型往往不自然；
- Context window 的容量按 token 计算，而不是按字数或页数计算。

因此，token 是理解 LLM 成本、上下文限制和认知缺陷的第一把钥匙。

## Part 2：神经网络如何学习下一个 token？

### 1. 输入与输出

从训练语料中截取一段 token 作为上下文，神经网络输出整个词表中每个 token 成为下一项的概率。

假设词表有 10 万个 token，网络就会输出约 10 万个分数。因为训练数据中真实的下一个 token 是已知的，所以可以：

1. 提高正确 token 的概率；
2. 降低其他 token 的相对概率；
3. 通过反向传播与梯度下降微调所有参数；
4. 在海量窗口和 token 上重复这一过程。

训练的结果是：模型给出的概率分布逐渐接近训练文本中真实的统计规律。

### 2. Transformer 内部在做什么？

Transformer 通常由多层重复模块组成，核心包括：

- **Embedding**：把离散 token ID 映射为连续向量；
- **Attention**：让当前位置读取上下文中相关 token 的信息；
- **MLP**：对每个位置的表示进行非线性变换；
- **残差连接与归一化**：维持深层网络的训练稳定性；
- **输出层**：把内部表示映射成下一个 token 的概率。

每个组件的数学操作是确定的，但数十亿参数怎样协作形成事实、语言风格和推理策略，仍无法像传统程序一样被完整解释。

### 3. 训练与推理的区别

| 阶段 | 行为 | 是否更新参数 |
|---|---|---|
| 训练 | 读取真实序列，计算预测误差，调整权重 | 是 |
| 推理 | 读取已有上下文，预测并采样下一个 token | 否 |

推理时的循环是：

```text
已有 token → 神经网络 → 下一个 token 的概率分布
                         ↓
                    选择或采样一个 token
                         ↓
                  追加到上下文，继续循环
```

### 4. 为什么同一个问题会得到不同回答？

模型输出的是概率分布，不是唯一答案。若从分布中采样，每次生成可能走上不同路径。

- 较低温度让分布更集中，输出更稳定；
- 较高温度增加多样性，也增加偏离高概率答案的机会；
- 一旦早期 token 不同，后续上下文也不同，整段输出会逐渐分叉。

这说明模型天然是随机系统。确定性可以通过解码策略增强，但不能把概率模型变成事实数据库。

### 5. 基础模型到底是什么？

预训练完成后得到的基础模型，可以看作“互联网文档模拟器”。给它一段网页、代码、论坛或新闻风格的开头，它会继续生成符合该类型统计规律的内容。

它拥有大量知识，却没有天然的用户—助手交互目标。直接给基础模型一个问题，它可能回答，也可能继续编写更多问题、生成网页格式或模拟一段对话。它完成的是续写，而不是“帮助用户”。

## Part 3：后训练——如何把基础模型变成助手？

### 1. 对话也必须变成一维 token 序列

人类看到的对话是结构化对象：系统、用户、助手、多轮消息。模型最终看到的仍是一维 token 序列，因此需要加入特殊 token 来标记：

- 一轮消息从哪里开始和结束；
- 当前内容来自系统、用户还是助手；
- 工具调用和工具返回值位于哪里；
- 模型何时应该停止生成。

不同模型的对话协议可能不同，但本质都是把结构编码进线性序列，再继续进行 next-token prediction。

### 2. 监督微调（SFT）是“用示例编程”

监督微调不需要改变核心训练算法，只需把训练数据从互联网文档换成高质量对话：

```text
用户：提出问题或任务
助手：给出理想回答
```

数据覆盖足够多的任务后，模型逐渐学会：

- 遵循指令；
- 使用清晰的回答格式；
- 维持多轮上下文；
- 在适当场景拒绝；
- 表现出“有帮助、真实、无害”的行为风格；
- 按特定协议调用工具。

这是一种隐式编程。规则不完全写在传统代码中，而是通过样本统计地进入参数。

### 3. 助手的“人格”从哪里来？

训练团队会制定详细标注规范，说明什么是理想回答。标注人员再根据这些规范创建或修订对话。模型学习的是这些回答的统计模式。

因此，普通助手模型可以被理解为：

> 一个对“遵循行为规范的专业标注者”进行快速神经网络模拟的系统。

这个心智模型可以祛除神秘感。输出既包含预训练获得的广泛知识，也包含后训练数据赋予的表达方式、价值取向和行为边界。

### 4. 从人工数据走向合成数据

早期对话数据主要由人从零编写，现代数据管线大量使用模型辅助：

- 模型生成候选回答，人类修订；
- 强模型生成训练样本，较小模型学习；
- 多个模型互相检查、重写或评分；
- 人类负责制定标准、抽检、纠错和覆盖关键边界场景。

数据由“纯人工生产”转向“模型生成 + 人类策划与监督”。不过最终能力仍受数据设计和质量控制约束。

## Part 4：LLM 的认知特点与锋利边缘

### 1. 幻觉不是偶发故障，而是生成机制的自然结果

如果训练数据中，“某人是谁”这类问题几乎总有一个自信完整的回答，模型就会学会这种形式。当用户询问一个不存在或模型不知道的人时，它仍可能生成统计上最像答案的内容。

模型内部可能已经存在“不确定”的信号，但如果训练数据没有把不确定性与“我不知道”这种输出连接起来，它仍会给出最可能的猜测。

#### 减少幻觉的两条路径

第一条是**校准模型对自身知识边界的表达**：

1. 从已知资料生成事实问题和正确答案；
2. 对同一问题多次采样模型回答；
3. 判断模型是否稳定知道答案；
4. 对不知道的问题，把“我不知道”作为正确训练样本；
5. 让模型学会在内部不确定性较高时拒绝猜测。

第二条是**允许模型检索**：

1. 模型生成搜索请求或工具调用；
2. 外层程序暂停生成并执行搜索；
3. 将搜索结果写入 context window；
4. 模型基于刚获得的资料作答并引用来源。

第一种方法让模型更诚实，第二种方法给模型补充事实。

### 2. 参数记忆与工作记忆

| 信息位置 | 类比 | 特点 |
|---|---|---|
| 模型参数 | 模糊的长期记忆 | 容量大、调用快，但不精确、有截止时间 |
| Context window | 当前工作记忆 | 直接可访问、处理更可靠，但容量有限 |
| 外部工具与数据库 | 可查询资料库 | 更准确、可更新，但需要检索和权限控制 |

实践上，如果任务依赖某篇文章、合同、数据表或代码，最好把相关内容直接提供给模型或使用检索系统，而不是要求模型“凭记忆”处理。

### 3. 模型没有天然的、持续存在的“自我”

一次推理通常是：加载参数、处理当前 token、生成输出，然后结束。下一次会话重新从参数和新的上下文开始。

模型关于“我是谁”的描述通常来自：

- 监督微调中的身份问答样本；
- 系统消息中写入的名称、开发者和能力边界；
- 互联网数据中最常见的助手身份模式；
- 当前对话上下文的暗示。

如果没有明确配置，模型可能对自身身份进行统计性猜测。因此，不能把模型的自我陈述自动当作系统事实。

### 4. 模型需要 token 来思考

Transformer 为每个新 token 执行一次有限深度的前向计算。它无法在一个 token 内完成任意复杂的运算。

如果回答一开始就要求给出最终数字，模型必须把所有推理压进产生该数字的一次前向计算；后面的解释只是对已经出现的答案进行事后合理化。

相反，先生成中间步骤可以把计算摊到多个 token 上：

```text
拆解问题
  ↓
生成中间结果
  ↓
把中间结果保留在上下文
  ↓
继续下一小步计算
  ↓
得到最终答案并复核
```

这些中间 token 主要是模型的计算草稿，不只是给人看的解释。

### 5. 推理过程仍不如工具可靠

让模型一步步写出心算过程通常比立刻给答案好，但神经网络仍可能在任一步算错。精确任务应优先调用确定性工具：

- 算术、统计：计算器或 Python；
- 数据筛选：SQL 或数据处理程序；
- 最新事实：搜索与数据库；
- 代码正确性：运行测试、类型检查、静态分析；
- 字符处理：字符串函数或正则表达式。

最好的模式不是“让模型更努力地猜”，而是让模型负责计划与解释，让可靠工具负责计算与验证。

### 6. Tokenization 导致拼写和计数缺陷

模型不直接看到字符，所以“某个单词有几个字母”“取每三个字符”“反转字符串”等任务，对它并不像对人类那样直观。

难点来自两层：

1. 单词被压缩成少数 token，字符边界不可直接访问；
2. 计数本身需要在有限单步计算中完成。

解决方法仍是工具化：让模型把字符串交给代码执行，而不是依靠神经网络心算。

### 7. 锯齿状智能 / 瑞士奶酪能力模型

LLM 的能力不是从简单到困难平滑递增的。它可能：

- 回答专业级科学问题；
- 完成复杂代码设计；
- 解出竞赛数学题；
- 同时在简单的小数比较、字符计数或异常格式上失败。

这种能力分布像瑞士奶酪：整体很大，但随机存在一些孔洞。用户很难仅凭任务“看起来简单”就判断模型一定可靠。

因此必须把 LLM 看作随机工具，而不是全知系统。

## Part 5：强化学习——从模仿专家到自主练习

### 1. 三阶段训练与学校教育的类比

| 模型训练 | 学校学习 | 学到什么 |
|---|---|---|
| 预训练 | 阅读课本正文 | 背景知识与语言规律 |
| 监督微调 | 阅读专家解题过程 | 如何组织回答、模仿专家方法 |
| 强化学习 | 独立完成练习题并核对答案 | 通过试错发现适合自己的解法 |

预训练让模型“知道很多”，SFT 让模型“看起来会做”，强化学习则让模型在大量练习中提高真正解决问题的成功率。

### 2. 为什么只模仿人类解法不够？

人类和模型的认知结构不同：

- 对人简单的一步，可能要求模型在单个 token 中完成过多计算；
- 人类写出的解释可能没有充分利用模型已经掌握的知识；
- 有些对人必要的步骤，对模型可能只是冗余；
- 标注者无法知道哪条 token 路径最适合模型。

SFT 可以把模型初始化到“接近正确解法”的区域，但更优的推理轨迹需要模型通过试错自己发现。

### 3. 可验证强化学习的基本流程

```text
给定问题和可验证答案
        │
        ▼
模型随机生成大量候选解法（rollouts）
        │
        ▼
自动检查每条解法的最终结果
        │
        ├── 错误路径：降低相似行为的概率
        └── 成功路径：提高相似行为的概率
        │
        ▼
在大量问题上反复更新模型
```

关键点是成功轨迹来自模型自己，而不是人工写好的专家答案。模型因此能发现与人类不同、但统计上更可靠的内部策略。

### 4. 推理策略如何涌现？

当奖励只关注最终正确性时，模型可能逐渐学会：

- 检查先前步骤；
- 发现矛盾后回退；
- 从另一种表示重新求解；
- 尝试多个方案；
- 在提交答案前交叉验证；
- 使用更多 token 换取更高准确率。

这些“等一下”“重新检查”“换个方法”的行为不必逐条写进训练样本，而可能从提高成功率的优化过程中自然出现。

这就是推理模型与普通助手模型的重要区别：普通助手主要模拟专家写好的答案，推理模型还经过大量可验证练习，优化了产生答案之前的计算过程。

### 5. 为什么强化学习可能超过模仿？

模仿学习的上限受示范者限制。强化学习只关心什么行为能得到正确结果，因此可以离开人类常用策略，探索新的路径。

在封闭、规则明确、结果可自动判定的环境中，这一点最明显：系统可以反复自我练习，不受人工数据规模限制，并发现低概率但有效的策略。

将这一思路扩展到语言模型，需要建立大量“练习环境”：数学题、代码任务、形式化证明、可执行工作流，以及其他能够自动判定成功与否的任务。

### 6. 可验证领域为什么特别重要？

理想奖励函数应当：

- 便宜；
- 自动化；
- 客观；
- 难以欺骗；
- 能够高频调用。

数学最终答案、代码测试结果、游戏胜负等较符合这些要求。系统可以长时间优化，因为“正确就是正确”，很难通过措辞欺骗判定器。

## Part 6：RLHF——不可验证任务中的偏好学习

### 1. 创意任务没有唯一正确答案

笑话、诗歌、摘要、文风和一般帮助性无法用简单程序判断。让人类评价每一次强化学习采样又过于昂贵，因此需要一个可反复调用的人类偏好代理。

### 2. 奖励模型如何产生？

典型过程是：

1. 对同一提示生成多个候选回答；
2. 让人类把候选回答从好到坏排序；
3. 训练一个独立的奖励模型，使其评分顺序接近人类排序；
4. 使用奖励模型代替人类，对大量新回答快速评分；
5. 让语言模型通过强化学习提高奖励分数。

奖励模型不是生成文字的助手，而是接收“提示 + 候选回答”，输出单个偏好分数的评分器。

### 3. RLHF 的优势

- 把强化学习扩展到没有标准答案的任务；
- 人类只需比较，不必亲自写出理想答案；
- 判断“哪个更好”通常比从零创作更容易；
- 能改进回答风格、帮助性和总体偏好表现。

### 4. 奖励模型的根本限制

奖励模型只是人类判断的有损模拟，不是真正的人类，也不是真理函数。大规模优化可能找到奖励模型的漏洞：某些人类看来无意义的输出，却被奖励模型错误打出高分。

这称为 reward hacking 或对抗性利用。常见规律是：

```text
优化初期：回答质量随奖励提高
        ↓
优化过度：模型开始寻找评分器漏洞
        ↓
奖励继续升高，但真实质量下降
```

可以把已发现的漏洞加入训练数据修补，但复杂神经网络通常还隐藏着更多对抗样本。因此，基于奖励模型的强化学习不能像规则明确的游戏那样无限运行。

结论是：RLHF 很有用，但更像一次有限的偏好微调，不能与可验证环境中的长期强化学习等同。

## Part 7：未来能力会沿哪些方向发展？

### 1. 原生多模态

文本、声音和图像都可以被编码成 token 流：

- 音频可以从频谱片段提取离散表示；
- 图像可以被拆分为 patch 并编码；
- 文本、图像和音频 token 可以交错进入同一上下文。

统一 token 接口使模型能够同时读写文字、听说语音、理解和生成图像，而不必把每种模态完全割裂开来。

### 2. 从单次回答走向长时间 Agent

普通对话通常把一个清晰任务直接交给模型。更进一步的系统需要：

- 自己拆解目标；
- 连续执行多个步骤；
- 调用浏览器、代码和外部应用；
- 检查结果并从错误中恢复；
- 管理长时间运行的状态；
- 在关键节点向人汇报和请求决策。

随着任务持续时间增长，人的角色会从逐步操作者转向监督者。但模型的锯齿状能力意味着，长任务不能简单地无人值守。

### 3. AI 会更隐形地进入现有工具

LLM 不一定总以独立聊天框出现。它可以成为编辑器、浏览器、办公软件、终端和业务系统中的意图理解层，并进一步操作键盘、鼠标、API 和企业流程。

能力越接近真实操作，权限控制、审计、确认和错误恢复就越重要。

### 4. Context window 不是长期学习

模型部署后，参数通常固定。一次会话中发生的“学习”主要是把新信息放进 context window；会话结束后，这些信息不会自动写回参数。

单纯扩展 context window 不能无限解决长期任务：

- 上下文是有限且昂贵的资源；
- 长时间多模态任务会产生极大 token 流；
- 有用信息会被噪声淹没；
- 模型需要更持久的记忆、压缩、检索或测试时学习机制。

因此，未来系统需要的不只是“更长上下文”，还包括有效的长期记忆与在线适应方法。

## Part 8：如何更可靠地使用 LLM？

### 1. 先判断信息应该来自哪里

| 任务 | 首选信息来源 |
|---|---|
| 常识、措辞、创意草稿 | 模型参数记忆 |
| 指定文章、合同、代码库 | 直接提供的上下文或 RAG |
| 最新事实、价格、法规 | 搜索、数据库、权威来源 |
| 数学、统计、数据处理 | 计算器、Python、SQL |
| 可执行结论 | 实际运行、测试或人工验证 |

### 2. 为模型提供足够的计算空间

复杂任务不要强迫模型“只给答案、不许解释”。更好的要求是：

- 先拆解问题；
- 列出必要假设；
- 生成并检查中间结果；
- 必要时使用工具；
- 最后单独给出简洁结论。

用户界面可以只展示摘要，但系统内部应允许模型进行足够的计算和验证。

### 3. 明确要求使用工具

当任务涉及精确计算、字符处理、实时信息或大量数据时，直接要求模型使用对应工具，通常比让它“再仔细想想”更有效。

### 4. 不要用语气判断正确性

模型的自信语气来自训练风格，并不是置信度仪表。可靠性应来自：

- 可追溯来源；
- 可重复计算；
- 测试结果；
- 多路径交叉验证；
- 专业人员复核。

### 5. 选择适合任务的模型模式

| 任务类型 | 合适模式 |
|---|---|
| 简单问答、改写、摘要 | 快速助手模型 |
| 复杂数学、代码、规划 | 推理模型或更高推理预算 |
| 私密且规模可控的任务 | 本地开放权重模型 |
| 需要最新信息 | 具备搜索或数据连接能力的模型 |

推理预算应与任务难度匹配。简单事实不需要长时间思考，复杂问题则不应强求瞬间回答。

### 6. 最终责任仍在人

把模型用于：

- 提供灵感；
- 生成第一版；
- 分析候选方案；
- 查漏补缺；
- 加速重复工作。

但不要把未经检查的输出直接作为最终产品。模型可以显著提高效率，却不能替代对结果负责的人。

## 常见误区

### 误区 1：模型把互联网原文完整存进参数

参数更像有损压缩与统计重构。模型可能记住部分高频文本，但整体上不是可以精确读取的文档数据库。

### 误区 2：模型能流畅解释，所以它一定理解并算对了

流畅度来自语言建模，解释可能是对错误结论的事后合理化。正确性需要外部验证。

### 误区 3：任务越简单，模型越不可能出错

LLM 的能力是锯齿状的。对人简单的字符、计数和异常格式任务，可能恰好位于能力孔洞中。

### 误区 4：更长的回答一定代表更强的推理

有用的是能提高正确率的搜索、回退和验证，不是单纯增加文字长度。

### 误区 5：助手说出的身份和能力边界来自真实自我认知

这些信息往往由训练样本和系统消息配置，不是模型天然拥有的持久自我。

### 误区 6：RLHF 可以无限提升模型

RLHF 优化的是可被欺骗的奖励模型。过度优化会导致奖励上升而真实质量下降。

### 误区 7：只要模型足够强，就不再需要工具

工具不是模型能力不足时的临时补丁，而是可靠系统的核心组成。搜索、代码和数据库提供了参数记忆无法保证的准确性和时效性。

## 最终认知模型

理解一个 LLM 系统时，可以连续问六个问题：

1. **它的数据从哪里来，经过了怎样的过滤？**
2. **它如何把输入转换为 token？**
3. **预训练让它获得了哪些知识与能力？**
4. **后训练把它塑造成了怎样的助手？**
5. **它是否经过可验证强化学习，能否为困难任务投入更多推理计算？**
6. **它可以调用哪些工具，结果如何验证，最终由谁负责？**

这六层共同决定了模型的能力、风格、成本、可靠性和风险。把它们分开理解，就不会把流畅语言误认为绝对知识，也不会因为模型存在缺陷而忽略它作为认知工具的巨大价值。
