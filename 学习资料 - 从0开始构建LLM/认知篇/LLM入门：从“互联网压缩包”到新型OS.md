#  LLM入门：从“互联网压缩包”到新型操作系统

## 大语言模型的本质

大语言模型本质上是一个通过“预测下一个 token”训练出来的神经网络：预训练把海量互联网文本压缩进参数，微调把它塑造成助手；当它再连接搜索、计算器、代码、图像和语音等工具后，就逐渐像一个以自然语言为界面的新型操作系统，但同时带来了越狱、提示注入和数据投毒等全新的安全问题。

## 关键点

1. **一个可运行的 LLM 可以被简化为两个文件：参数文件 + 推理代码。** 代码描述网络结构，参数承载训练所得的能力与知识。
2. **预训练的核心任务只是预测下一个 token。** 目标看似简单，却迫使模型学习语法、事实、风格以及大量世界规律。
3. **参数可视为互联网的有损压缩。** 它保存的是统计规律和模糊知识，不是可精确查询的数据库。
4. **基础模型不是聊天助手。** 它更像“互联网文档续写器”；高质量对话数据微调后，它才表现为会回答问题的助手。
5. **微调主要改变行为与表达形式，不会把模型变成绝对可靠的事实库。** 幻觉是生成机制的自然结果，不能仅靠“更像助手”来消除。
6. **LLM 的能力不只来自模型本身，也来自工具。** 搜索、计算器、Python、检索系统和图像模型能补足记忆、算术和执行能力。
7. **更合适的长期比喻是“LLM OS”。** LLM 像内核，context window 像工作内存，外部数据像磁盘或互联网，工具像外设与系统调用。
8. **能力越强，攻击面越大。** 多语言、多模态、联网和文件访问在增强能力的同时，也带来越狱、提示注入、隐私泄露和数据投毒风险。

## Part 1：LLM 到底是什么？

### 1. 两个文件：参数与运行代码

以 Llama 2 70B 为例，一个 LLM 可以被极度简化为：

- **参数文件**：700 亿个参数，若每个参数用 16 位浮点数保存，体积约为 140 GB；
- **运行代码**：实现 Transformer 前向计算的程序，概念上几百行 C 代码就能写出最小版本。

把两者放在一台足够强的本地计算机上，即使不联网，也可以输入文本并让模型继续生成。这里要区分两件事：

| 阶段 | 在做什么 | 主要特点 |
|---|---|---|
| 训练（training） | 从大量数据中求出参数 | 昂贵、耗时、依赖大规模 GPU 集群 |
| 推理（inference） | 用既有参数逐 token 生成内容 | 相对便宜，可以在本地或服务器运行 |

模型的网络结构和数学运算并不神秘，真正凝聚能力的是训练得到的巨量参数。

### 2. 预训练：把互联网压缩进参数

以 Llama 2 70B 为例，其预训练大致是：收集约 10 TB 文本，使用约 6000 张 GPU 训练约 12 天，成本约 200 万美元，最后得到约 140 GB 参数。这一组数据仅用于帮助理解训练的量级，并不代表当前前沿模型的规模与成本。

可以把结果想成一个“互联网压缩包”，但它与普通 ZIP 有根本差别：

- ZIP 是无损压缩，可以恢复原文件；
- LLM 参数是有损压缩，只保留数据中的统计结构、关联和整体形态；
- 因此模型会记住一些内容、概括一些规律，也会把合理的形式与错误的细节混合起来。

这个比喻解释了为什么 LLM 既能展示广博知识，又会一本正经地编造事实。

### 3. 为什么“预测下一个 token”能产生智能？

训练时，模型看到一段 token 序列，然后预测下一项的概率分布。选出一个 token 后，再把它放回输入，继续预测下一项，如此循环形成完整文本。

要准确预测下一个 token，模型不能只学词频。例如要续写一段人物介绍，它需要隐式掌握人物、年代、事件、语言习惯和上下文关系。随着训练数据和参数规模增长，这些知识与模式被分散编码进神经网络。

可以用下面这条因果链理解：

```text
更准确地预测下一个 token
        ↓
必须识别文本中的规律与上下文
        ↓
必须压缩语言、事实和世界模式
        ↓
参数中出现可迁移的知识与能力
```

### 4. 模型是在“回忆”，还是在“做梦”？

基础模型从互联网文档分布中采样，因此它很像在“梦见网页”：可能生成代码、商品页或百科文章的样子。格式通常非常逼真，但书名、作者、ISBN 或具体事实可能根本不存在。

有些输出来自训练数据的记忆，有些是知识的概括，还有些只是统计上看起来合理的补全。用户通常无法从措辞本身判断它属于哪一种，所以：

> 流畅不等于正确，自信也不是可靠性的证据。

### 5. 我们知道结构，却还没有完全理解内部机制

Transformer 的每一步数学运算都是已知的，训练算法也能持续降低预测误差；但数十亿参数如何协同形成具体知识、推理和行为，仍难以完整解释。

LLM 可以被视为一种主要靠实验认识的“经验性产物”：我们给它输入、观察输出、统计成功率，再通过评测判断它是否适合某个任务。机械可解释性研究正在尝试打开这个黑箱，但目前不能像检查传统程序那样完整说明每个内部部件的作用。

这意味着实际应用不能只看几个演示，必须建立覆盖真实场景的评测集。

## Part 2：基础模型如何变成聊天助手？

### 1. 预训练负责“知识”，微调负责“行为”

预训练后得到的是基础模型。它学会续写互联网文档，却不天然知道用户希望它回答问题。要把它变成助手，需要把训练数据换成高质量的对话：

```text
用户：提出问题或任务
助手：给出符合规范的理想回答
```

训练目标仍然是预测下一个 token，改变的是数据分布。模型由此学会遵循指令、使用问答格式，并表现得有帮助。

两个阶段可以这样区分：

| 维度 | 预训练 | 监督微调（SFT） |
|---|---|---|
| 数据 | 海量互联网文本 | 少量但高质量的人工或机器辅助对话 |
| 目标 | 获得通用知识与语言能力 | 学会指令遵循、回答风格和行为边界 |
| 成本 | 极高，迭代较慢 | 相对较低，可频繁迭代 |
| 产物 | 基础模型 | 助手模型 |

微调并不是给模型装入一个可靠数据库，而是把原先的“网页梦”引导成“有帮助的助手梦”。因此，它仍可能幻觉。

### 2. 从失败案例反向改进

助手部署后，需要持续收集失败案例：

1. 找到模型的不良或错误回答；
2. 让标注者写出理想回答；
3. 把新样本加入微调数据；
4. 再训练、再评测、再部署。

这是一条持续的数据闭环。很多产品差异并不只来自基础模型大小，也来自标签规范、数据质量、评测体系和迭代速度。

### 3. RLHF：比较答案通常比从零写答案容易

除了让人直接写理想答案，还可以让模型先生成多个候选答案，再让标注者进行排序。对许多任务，人类判断“哪个更好”比亲自写出最佳答案容易。

这些偏好比较可以用于强化学习人类反馈（RLHF），进一步提升模型的有用性、真实性与无害性。数据生产也正在从纯人工转向人机协作：模型先起草、检查或比较，人类负责筛选、修订和监督。

## Part 3：LLM 为什么还会继续变强？

### 1. Scaling Laws：规模带来可预测的收益

从经验规律看，模型的预测性能主要随两个变量平滑变化：

- `N`：模型参数数量；
- `D`：训练数据量。

增加模型规模和训练数据，通常会稳定改善 next-token prediction 的损失；而这种改善又与多项下游能力相关。这种可预测性推动了算力、数据和 GPU 集群的“淘金热”。

需要注意：规模化是一条重要路径，却不是无条件保证所有真实任务都按比例改善。数据质量、训练方法、推理资源、工具系统和评测设计同样关键。

### 2. 工具调用：不要只让模型“在脑中算”

LLM 的参数记忆模糊、数学计算不稳定、知识还有截止日期。解决办法是让它按任务选择工具：

| 局限 | 可调用的工具 | 作用 |
|---|---|---|
| 不知道最新事实 | 浏览器、搜索、数据库 | 检索最新、可引用的信息 |
| 算术不可靠 | 计算器 | 得到精确结果 |
| 数据分析和绘图复杂 | Python、代码解释器 | 执行计算并生成图表 |
| 需要内部资料 | RAG、文件检索 | 把相关资料放入上下文 |
| 需要视觉内容 | 图像生成模型 | 将自然语言意图转为图像 |

模型可以输出特殊 token 或结构化调用，由外层程序识别并执行工具，再把结果送回上下文，模型据此继续生成。

真正强大的系统不是“一个无所不知的模型”，而是“一个会判断何时调用何种工具的协调器”。

### 3. 多模态：从读写文字到看、听、说和生成

LLM 的输入输出正从纯文本扩展到图像和音频，主要方向包括：

- 看懂手绘网页草图并生成 HTML/JavaScript；
- 根据文字生成图片；
- 理解图片中的内容；
- 通过语音进行自然的双向对话。

多模态让自然语言成为更通用的人机接口，但图像、音频也会变成新的攻击载体。

### 4. 从 System 1 走向 System 2

可以借用《思考，快与慢》中的概念来理解两种推理模式：

- **System 1**：快速、直觉式、自动反应；
- **System 2**：慢速、刻意、会展开多个可能、检查和回退。

当时的 LLM 主要是等速地逐 token 生成，更接近 System 1。理想的未来系统应能把更多推理时间转化为更高准确率：提出候选方案、搜索思路树、反思、验证、回退，最后再作答。

这里的关键认知不是“输出越长越聪明”，而是系统是否真的利用额外计算进行搜索与验证。

### 5. 自我改进：寻找语言世界里的 AlphaGo 闭环

AlphaGo 先模仿高手棋谱，再通过自我对弈和明确的胜负奖励超过人类。LLM 也能模仿高质量人类答案，但通用语言任务缺少便宜、客观、自动的奖励函数，因此很难直接复制 AlphaGo 的自我改进路径。

在答案可以自动验证的窄领域，例如部分数学、代码和形式化任务，更容易建立：

```text
生成多个方案 → 自动验证 → 保留成功轨迹 → 继续训练
```

通用任务如何定义可靠奖励，仍是核心难题。

### 6. 定制化：从一个通用助手到大量专家模型

不同组织和行业需要不同知识、流程和行为边界。定制模型的手段包括：

- 系统指令与工作流规则；
- 上传文件并通过 RAG 检索；
- 连接业务工具与数据库；
- 使用领域数据微调。

未来更可能出现由多个专业化模型或智能体协作的生态，而不是一个模型包办一切。

## Part 4：LLM OS——一种新的计算栈

把 LLM 仅看作聊天机器人或文字生成器会低估它。更贴切的比喻是：**LLM 正成为一种新操作系统的内核进程，负责理解自然语言意图、协调信息和调用工具。**

| 传统计算机 | LLM 系统中的对应物 |
|---|---|
| CPU / 内核进程 | 基础模型与推理过程 |
| RAM | Context window（有限的工作记忆） |
| 硬盘 / 网络存储 | 本地文件、知识库、互联网 |
| 外设 / 系统工具 | 浏览器、计算器、Python、图像与音频模型 |
| 应用程序 | 面向具体任务的定制助手或智能体 |
| GUI / 命令行 | 自然语言、多模态交互界面 |

Context window 是有限且宝贵的资源。系统需要不断决定哪些资料应该载入、保留、压缩或移出，就像操作系统管理内存。

这个比喻还暗示了两个生态方向：一类是闭源、统一体验的专有平台；另一类是围绕开放权重模型形成的可定制生态，类似桌面操作系统中的 macOS/Windows 与 Linux 系谱。

## Part 5：新的计算范式，也有新的安全问题

### 1. Jailbreak（越狱）

越狱的目标是绕过模型原有的安全行为。攻击者可能使用角色扮演、不同语言或编码、自动优化出的无意义后缀，甚至对人眼几乎不可见的图像噪声。

难点在于：模型学到的拒绝行为往往只覆盖训练数据中的表达方式，而输入空间几乎无限。修补某个具体提示并不能保证相似变体失效。

### 2. Prompt Injection（提示注入）

提示注入不是直接要求模型违反规则，而是把恶意指令藏在模型读取的外部内容中，例如：

- 网页里的隐藏文字；
- 图片中的淡色指令；
- 被分享的文档；
- RAG 知识库里的污染内容。

当模型无法可靠区分“数据”和“指令”时，外部内容就可能劫持任务。联网、读文件和调用工具越多，风险越大。严重情况下，攻击者可能诱导模型泄露私有数据或执行错误操作。

### 3. Data Poisoning / Backdoor（数据投毒与后门）

攻击者污染训练或微调数据，让模型在看到特定触发词时表现异常。平时模型可能完全正常，只有触发条件出现时才执行攻击者预设的行为，因此不易通过普通测试发现。

### 4. 安全是一场持续的攻防循环

具体攻击可以被修复，但新的变体会继续出现。LLM 安全与传统系统安全一样，是持续的猫鼠游戏，而不是一次性解决的问题。

对实际系统的启示：

- 不把网页、文档、邮件或图片里的文字自动视为可信指令；
- 严格限制模型能够调用的工具和数据权限；
- 对高风险动作增加确定性的程序校验和人工确认；
- 隔离私密数据与不可信内容；
- 记录工具调用链并做红队测试；
- 把“模型可能被操纵”当成基础威胁模型，而不是边缘情况。

```text
互联网文本
   │
   │ 预训练：预测下一个 token
   ▼
基础模型（知识与语言模式）
   │

   │
   └── 必须防范：越狱、提示注入、数据投毒、权限滥用
```

## 对个人使用 LLM 的实践建议

1. **先判断任务类型。** 创意写作可以容忍采样；事实、数学、代码和决策任务必须验证。
2. **要求模型使用来源。** 对时效性事实优先搜索或检索，不依赖参数记忆。
3. **把复杂任务拆开。** 先列计划，再逐步执行，并在关键节点检查中间结果。
4. **让工具做擅长的事。** 数学交给计算器，数据处理交给代码，最新事实交给检索。
5. **提供必要上下文。** 模型的工作记忆有限，相关资料、约束和评价标准要明确给出。
6. **把输出当草稿。** 重要内容需要交叉核验、运行测试或由领域专家复审。
7. **谨慎连接权限。** 当模型能读私有文件、发消息或执行命令时，要使用最小权限和操作确认。

## 最后的认知模型

理解 LLM 时，不要只问“它会不会回答这个问题”，而应同时问四件事：

1. **模型本身学到了什么？**——来自预训练参数的模糊知识与模式。
2. **它被训练成怎样行动？**——来自微调、偏好数据和行为规范。
3. **它能调用什么？**——检索、代码、多模态和其他外部工具。
4. **它可能怎样失败或被攻击？**——幻觉、提示注入、数据投毒和权限滥用。

把这四层分开，就能更准确地判断一个 LLM 系统的能力边界、可靠性与风险。
