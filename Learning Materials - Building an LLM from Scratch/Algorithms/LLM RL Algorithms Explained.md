# Reinforcement Learning for LLMs: From RLHF and PPO to GRPO, DAPO, and GSPO

> Reinforcement learning for LLMs is not simply a matter of swapping in a new loss function. It is an online loop that combines policy sampling, reward construction, advantage estimation, policy constraints, and distributed rollouts. This chapter explains PPO, REINFORCE/RLOO, ReMax, GRPO, Dr.GRPO, DAPO, and GSPO; distinguishes RLHF, RLAIF, RLVR, and DPO; and concludes with practical next steps for miniLLM.

## 1. Where RL Fits in the LLM Training Pipeline

A typical modern training pipeline is:

```text
tokenizer
  -> Pretraining / Mid-training
  -> SFT / Reasoning Cold Start
-> Offline Preference Optimization (DPO, etc., optional)
-> Online RL (PPO / RLOO / GRPO, etc., optional)
-> Safety, Eval, Distillation and Deployment
```

Each stage provides a different kind of supervision:

| Stage | Data or Feedback | What the Model Learns |
|---|---|---|
| SFT | Target responses written by people or a teacher model | Imitate what a good answer looks like |
| Offline preference optimization, such as DPO | Fixed chosen/rejected pairs | Increase the likelihood of chosen responses relative to rejected ones |
| RLHF / RLAIF | A reward model trained on human or AI preferences | Maximize preference reward on new responses sampled from the current policy |
| RLVR | Answers checked by tests, compilers, formal systems, or other verifiers | Discover new high-reward trajectories through verifiable outcomes |
| Agent RL | Environment state, tool results, and task success or failure | Learn multi-step decisions, recovery, and stopping behavior |

SFT learns from fixed target responses. The defining difference in online RL is that **the changing policy continually generates new training data**. Exploration, reward loopholes, policy staleness, and system throughput therefore directly affect the capabilities that emerge.

## 2. First, clarify the concepts of three groups that are often mixed.

### 2.1 RLHF, RLAIF, RLVR: Where does the reward come from?

- RLHF (Reinforcement Learning from Human Feedback): The reward model mainly learns human preferences;
- RLAIF (Reinforcement Learning from AI Feedback): Preferences or scores are mainly generated by another model based on the rules;
- RLVR (Reinforcement Learning with Verifiable Rewards): Rewards come from executable and verifiers;
- Agent RL: Reward task completion from real or simulated environments, and may also be mixed with human, AI and rule feedback.

These names describe **feedback source and training paradigm**, not a fixed optimizer. RLHF can use PPO or RLOO; RLVR can use GRPO or PPO.

### 2.2 PPO, RLOO, GRPO, GSPO: How to estimate and update the gradient

These are the strategy optimization algorithms. They are mainly different in the following issues:

- Whether to train Value/Critic;
- How to estimate Advantage;
- How many answers are sampled for each prompt;
- Importance Ratio is defined by token or Sequence;
- Whether Clip, How To Do KL Constraint;
- Loss is aggregated by token, Sequence or prompt.

### 2.3 reward model, Verifier, Judge: How to score answers

- reward model: the learned scalar model, usually input prompt and output score after answering;
- Verifier: judged according to standard answers, code tests or formal rules, which is usually more objective;
- LLM Judge: Using a large model to score according to Rubric, it is essentially a learning evaluator that can still be used;
- Process reward model (PRM): Score the intermediate steps instead of just looking at the final results.

No matter how stable the optimizer is, it cannot make up for the wrong reward. The upper limit of the large model RL is often determined by "whether the reward represents the real goal".

## 3. Write language generation as a reinforcement learning problem

Given prompt (x), the model generates an answer (y=(y_1,\ldots,y_T)). The generation process can be regarded as token-level MDP:

```text
Status s_t = prompt + Generated token y_<t
Action a_t = Next token y_t
Transfer = add y_t to the context
Terminate = Generate EOS or reach the length limit
Reward = final result reward, which can also include intermediate step rewards
```

Strategy is a language model:

\[
\pi_\theta(y\mid x)=\prod_{t=1}^{T} \pi_\theta(y_t\mid x,y_{<t})
\]

The simplest goal is to maximize the expected reward:

\[
J(\theta)=\mathbb E_{x\sim D,\,y\sim\pi_\theta(\cdot\mid x)} [R(x,y)]
\]

The general alignment scenario also often adds the KL constraint of the relative freezing reference policy \(\pi_{ref}\):

\[
J(\theta)=\mathbb E[R(x,y)]- \beta\mathbb E\left[ \log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)} \right]
\]

The function of KL is not to keep the strategy completely unchanged, but to limit the speed at which the strategy leaves the reference distribution and reduce the risk of the reward model being used outside the distribution.

## 4. Don't confuse the three models: Policy, Old Policy, Reference

In the implementation of online RL, it often appears at the same time:

| Name | Whether to change | Function |
|---|---|---|
| \(\pi_\theta\) Policy / Actor | Each optimization update | The generation model to be trained at present |
| \(\pi_{old}\) Old / Behavior Policy | Synchronization after each round of Rollout | Which version of the record sample is generated for Importance Ratio |
| \(\pi_{ref}\) Reference Policy | Usually Freeze | Provide KL anchor points to prevent the strategy from drifting too far |

\(\pi_{old}\) and \(\pi_{ref}\) are not the same thing. The former solves the problem that On-policy data becomes old after multi-step updates; the latter defines the behavioral benchmark of "don't deviate too far". Some RLVR formulas will remove \(\pi_{ref}\), but still need to record or reproduce the sampling log probability of \(\pi_{old}\).

## 5. Reward: The real optimization goal of RL system

### 5.1 Preference reward model

Give the same prompt's preferred answer \(y_w\) and non-preferenced answer \(y_l\), the classic Bradley–Terry form is:

\[
P(y_w\succ y_l\mid x)= \sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right)
\]

reward model Minimization:

\[
L_{RM}=-\log\sigma\left( r_\phi(x,y_w)-r_\phi(x,y_l) \right)
\]

After the training is completed, Policy generates a new answer, and reward model outputs the scalar score. Special precautions are required:

- Surface deviations such as length, format, tone and number of citations;
- reward model is only reliable in the distribution of old strategies;
- The labeler's differences are compressed into a single scarar;
- Policy to find a shortcut with high rewards but low real quality;
- The Reward score continued to rise, but the artificial win rate decreased.

### 5.2 RLAIF and LLM-as-a-Judge

RLAIF uses principles, Rubric or constitutions to let the strong model generate preference labels, and then trains the reward model or directly uses the Judge score as a reward. The advantage is that it is easy to expand and cover complex rules; the risk is Judge's position deviation, length deviation, self-preference and can be manipulated by prompt Injection.

AI Feedback is not the same as automatic correctness. High-risk scenarios still require manual calibration, counter-samples and independent evaluators.

### 5.3 RLVR

RLVR is suitable for tasks with objective results:

- Mathematics: compare the final answer after normalization;
- Code: compilation, unit testing, static inspection and resource limitation;
- Formal certificate: checked by Proof assistant;
- Structured output: JSON Schema, SQL execution results;
- Tool task: whether the environmental status has reached the target.

The simplest binary reward is:

\[
R(x,y)=\mathbb 1[\operatorname{verify}(x,y)=\text{pass}]
\]

Verifier is usually more difficult to deceive than the learning reward model, but the parser and test itself may still have loopholes. Only verify the final string, and it may also reward guessing the answer, hard coding or using the test gap.

### 5.4 Outcome Reward and Process Reward

Outcome Reward only evaluates the final answer, which is cheap but rough in credit allocation; Process Reward gives feedback to intermediate steps, and the signal is more dense, but labeling or automatic verification is more difficult.

Common uses of PRM include:

- Incremental rewards for each step in RL;
- Search or rearrase multiple trajectories at inference time;
- Filter Reasoning SFT data;
- Find the trajectory of the correct answer but the wrong process.

Process supervision may also mistake a certain writing style for reasoning quality, which must be checked with the success rate of the final task.

### 5.5 multi-target reward

Production systems often combine multiple goals:

\[
R=w_{task}R_{task}+w_{safe}R_{safe}+w_{style}R_{style} -w_{cost}C_{tokens}-w_{viol}C_{violation}
\]

Fixed linear weighting is simple, but it will allow a high-scoring dimension to compensate for unacceptable security failures. Hard restraint, safety Gate or phased training are sometimes more appropriate than single-weighted and.

## 6. Policy Gradient: the common base of all mainstream online algorithms

The gradient of REINFORCE is estimated to be:

\[
\nabla_\theta J(\theta) =\mathbb E\left[ (R-b)\sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t}) \right]
\]

Among them, \(b\) is the Baseline that does not depend on the current action. It does not change the expected gradient, but can reduce the variance. Definition Advantage:

\[
A=R-b
\]

Intuitively:

- \(A>0\): Increase the probability of action in this sampling trajectory;
- \(A<0\): Reduce their probability;
- The bigger \(|A|\): the stronger the update.

When rewards only appear at the end of the answer, all tokens of the same Sequence often share the same Outcome Advantage. This estimate is simple, but it is difficult to judge which step is the success or failure.

## 7. PPO: The main baseline of classic RLHF

### 7.1 Core Objectives

The sample is generated by \(\pi_{old}\), and the token-level Importance Ratio of the current Policy and the old Policy is:

\[
\rho_t(\theta)= \frac{\pi_\theta(y_t\mid x,y_{<t})} {\pi_{old}(y_t\mid x,y_{<t})}
\]

PPO-Clip Maximization:

\[
J_{PPO}=\mathbb E_t\left[ \min\left( \rho_t\hat A_t, \operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t \right) \right]
\]

Clip limits one update to push the new strategy too far from the sampling strategy, so that a batch of Rollout can safely carry out several rounds of Mini-batch updates.

### 7.2 Critic and GAE

Classic PPO training Value Model \(V_\psi(s_t)\) predicts the return from the current state. Temporal Difference is:

\[
\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)
\]

Generalized Advantage Estimation (GAE) is:

\[
\hat A_t=\sum_{l=0}^{T-t-1}(\gamma\lambda)^l\delta_{t+l}
\]

Complete Loss usually includes:

\[
L=-J_{PPO}+c_vL_{value}-c_eH(\pi_\theta)
\]

Then cooperate with the Reference KL punishment in Reward.

### 7.3 What components are required for the classic PPO-RLHF?

```text
prompt
-> Actor sampled answer
-> reward model Score
-> reference model Calculation KL
-> Critic estimates the value of each token
-> GAE Computing Advantage
-> Actor / Critic updated separately
```

Therefore, a classic system may maintain the four models of Actor, Critic, Reward and Reference at the same time. Even if some models share Backbone, their GPU memory, communication and scheduling are still expensive.

### 7.4 Advantages and limitations of PPO

Advantages:

- Mature, universal, suitable for a multi-step environment with intermediate rewards;
- Critic can assign different Advantages for different tokens or states;
- For multiple consecutive rounds of Agent trajectory, it is more natural than a single Outcome Baseline;
- Clip, KL, Value Loss and Entropy provide a variety of stable control means.

Limitations:

- Critic occupies a large amount of video memory and may be more difficult to train than Policy;
- Hyperparameters are coupled to each other, and Value misalance will pollute Actor;
- Multiple updates of the same batch of Rollout will produce Off-policy deviations;
- token Mask, KL, GAE and Padding are easy to misalign in the implementation;
- The system may be too complicated for single-round LLM tasks with only final scalar rewards.

PPO is still an important baseline for general RLHF and Agent RL, but it is no longer the default unique choice for all LLM RL scenarios.

## 8. REINFORCE Family: Simple Route to Remove Critic

### 8.1 Vanilla REINFORCE

Directly use the full return minus batch Mean, moving average or other Baseline. It has low display memory and clear implementation, but the single sample variance is large, and it is sensitive to Reward Scale and batch Size.

### 8.2 RLOO: REINFORCE Leave-One-Out

Answer to the same prompt sampling \(G\). The answer of \(i\) uses the average reward of the remaining answers as the Baseline:

\[
b_i=\frac{1}{G-1}\sum_{j\ne i}R_j, \qquad A_i=R_i-b_i
\]

It has several practical features:

- Don't train Critic;
- Relative comparison within the same prompt can eliminate the difference in difficulty of some questions;
- Leave-one-out Avoid putting the sample's own Reward into its Baseline;
- The algorithm is simpler than PPO, but the Rollout cost increases with \(G\).

Both RLOO and GRPO use the same prompt multi-sample as a comparative advantage. The difference is that RLOO is closer to direct REINFORCE, and usually does not rely on intra-group standard deviation normalization and PPO token Clip.

### 8.3 ReMax

ReMax generates an answer with Greedy Decoding for each prompt, with its Reward as Baseline:

\[
A=R(y_{sample})-R(y_{greedy})
\]

It also doesn't need Critic. Baseline is strongly related to the current prompt. The price is to do an extra Greedy Rollout for each prompt, and the quality and stability of the Greedy Baseline will affect the variance.

### 8.4 REINFORCE++

REINFORCE++ is a kind of scheme that combines Advantage normalization, PPO style Clip, KL and training stability skills into Critic-free REINFORCE. Its meaning is closer to "simplify the engineering formula of PPO", rather than changing the basic principle of Policy Gradient.

## 9. GRPO: The most representative Critic-free algorithm in reasoning RL

Group Relative Policy Optimization (GRPO) is systematically proposed by DeepSeekMath. For each prompt sampling \(G\) answer, the group will be normalized and rewarded:

\[
\hat A_i= \frac{R_i-\operatorname{mean}(R_1,\ldots,R_G)} {\operatorname{std}(R_1,\ldots,R_G)+\varepsilon}
\]

Then assign the Advantage of the same answer to the token of the answer, and use the PPO-style Importance Ratio and Clip:

\[
J_{GRPO}=\frac{1}{G}\sum_{i=1}^{G}\frac{1}{|y_i|} \sum_t \min\left( \rho_{i,t}\hat A_i, \operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i \right)
\]

The original GRPO can also add KL punishment to the Reference Policy.

### 9.1 Why GRPO is suitable for mathematics and code

- Verifier can give a stable Outcome Reward for each complete answer;
- Multiple sampling on the same topic naturally forms the Baseline of "who is better than peers";
- There is no need to train Critics of the same level as Policy separately;
- Multi-sample exploration can find new solutions that are not available in SFT data;
- The absolute score scale of the relative reward in the group for different questions is relatively stable.

### The key cost of 9.2 GRPO

Saving Critic is not the same as saving calculation. If each question samples \(G=8\) or \(16\) strip-length CoT, Rollout token often becomes the biggest cost. Training efficiency is mainly due to:

\[
\text{prompt number}\times G\times\text{average generation length}
\]

Decide, not just look at the training batch Size.

### 9.3 Zero variance group

Under the binary correctness reward, if a group of answers are all wrong or all right:

\[
R_1=R_2=\cdots=R_G
\]

Then the centralized Advantage is all 0, and this prompt does not produce an effective Policy Gradient. All wrong usually means that the question is too difficult or not explored enough; all right means that the question is too simple. Should be recorded continuously:

- `all_zero_group_ratio`;
- `all_one_group_ratio`;
- `nonzero_advantage_ratio`;
- The effective gradient rate of each difficulty bucket.

### 9.4 GRPO is not the magic of "let the model learn to reason automatically"

RL can only improve the probability of the high reward trajectory that has been sampled. If Base Policy never produces the correct answer under a given sampling budget, Binary Reward has no positive sample to amplify. Trainability dependency:

- Domain capabilities of base model;
- Can prompt Template activate the answer behavior;
- Whether the temperature, Top-p and maximum length are allowed to be explored;
- Whether the difficulty of the question is within the learning boundary of the current strategy;
- Whether Verifier can identify real success.

## 10. Dr.GRPO: Correction of length and difficulty weighting deviation

The analysis of Dr. GRPO indicates that common GRPO targets may include two implicit weightings:

1. Each answer is divided by its own length \(|y_i|\), which changes the total gradient weight of answers of different lengths;
2. Each question Advantage is dided by the standard deviation of Reward in the group, so that the weight of the questions of different Reward variances is different.

It proposed:

- Advantage only centralizes within the group, not divided by the standard deviation within the group;
- The denominator of token Loss uses fixed generation budget and other constants, and does not change according to the actual length of each answer.

\[
\hat A_i=R_i-\operatorname{mean}(R_1,\ldots,R_G)
\]

The goal is to avoid short correct answers being abnormally amplified, long wrong answers being relatively less punished, and questions of different difficulty from being re-weighted by Reward standard deviation.

There is no unique Reduction out of the task here: normalization according to sample average, effective token average and fixed length, corresponding to different optimization goals. In engineering, the denominator must be explicitly written and the length of the barrel must be melted. Only one `loss.mean()` cannot be recorded.

## 11. DAPO: GRPO system formula for long CoT

The full name of DAPO is Decoupled Clip and Dynamic Sampling Policy Optimization. It is based on Group-based, PPO-Clip style optimization, and the public formula contains four key techniques.

### 11.1 Clip-Higher

Change the symmetric Clip to asymmetric range:

\[
\operatorname{clip}(\rho,1-\epsilon_{low},1+\epsilon_{high}), \qquad \epsilon_{high}>\epsilon_{low}
\]

The higher upper bound gives the exploration token, which was originally low-probability but obtained positive Advantage, a greater room for improvement, which is used to alleviate the premature collapse of Entropy.

### 11.2 Dynamic Sampling

Filter zero gradient groups with all right and all wrong, and continue to sample until you get enough prompt Groups with Reward differences:

\[
0<\#\{i:R_i=1\}<G
\]

It can reduce invalid updates, but it will push the training distribution dynamics to the topic of "the current model happens to be sometimes, sometimes not". The original prompt distribution and the resampling distribution must be recorded to avoid unintentional loss of difficult or simple subdomains.

### 11.3 token-level Policy Gradient Loss

DAPO summarizes and averages all valid generated tokens in a batch:

\[
J=\frac{1}{\sum_i|y_i|} \sum_i\sum_t L_{i,t}
\]

Instead of averaging each answer according to the length first, and then averaging the answer. In This Way, Each token In The Long CoT Will Not Be Automatically Downgraded Because The Sequence Is Long. The price is that the long answer naturally contributes more gradients in batch, so the length bias still needs to be monitored separately.

### 11.4 Overlong Reward Shaping

Answers that exceed the upper limit of generation may only be cut off, and the direct reward will confuse "unfinished correct ideas" with "meaningless repetition". DAPO use:

- Filter the Loss of the truncated sample; or
- Gradually increase Soft Penalty in the buffer area close to the upper limit.

This is smoother than suddenly jumping from normal Reward to punishment, and also requires the log to distinguish between natural EOS and Max-length Truncation.

### 11.5 How to understand DAPO

DAPO is not a completely different new theoretical base from Policy Gradient. It is more suitable to be regarded as a set of algorithms for large-scale long CoT RL - the system joint formula: it modifies Clip, sampling distribution, Loss Reduction and truncation reward at the same time.

## 12. GSPO: Switch from token-level Clip to Sequence-level Clip

Group Sequence Policy Optimization (GSPO) believes that when the reward is granted to the whole Sequence, Off-policy Correction and Clip should also be based on Sequence.

It defines the Sequence-level Importance Ratio of length normalization:

\[
s_i(\theta)= \left( \frac{\pi_\theta(y_i\mid x)} {\pi_{old}(y_i\mid x)} \right)^{1/|y_i|} =\exp\left( \frac{1}{|y_i|}\sum_t \log\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})} {\pi_{old}(y_{i,t}\mid x,y_{i,<t})} \right)
\]

Then Make A Clip For The Whole Answer:

\[
J_{GSPO}=\frac{1}{G}\sum_i \min\left( s_i\hat A_i, \operatorname{clip}(s_i,1-\epsilon,1+\epsilon)\hat A_i \right)
\]

### 12.1 What problems does GSPO solve?

- Reward and optimization units are both at the Sequence level;
- Avoid the ratio abnormality of a few tokens to determine the Clip status of the entire trajectory;
- The difference in log probability values between Rollout Engine and Training Engine is more stable;
- The public results emphasize their help to the stability of MoE RL training.

### 12.2 Precautions when using

- GSPO's \(\epsilon\) and token-level PPO/GRPO are not on the same numerical scale and cannot be copied;
- Sequence Ratio has been normalized in length, and it is still necessary to check the actual gradient weight of different lengths;
- Only the final Sequence Reward is the most natural; multi-round and step-by-step rewards require finer GSPO-token or other Credit Assignment;
- It is a relatively new public scheme, which should be compared with the mature GRPO/PPO baseline on its own model and system.

## 14. The relationship between DPO and RL: adjacent but not equivalent

DPO uses fixed preferences for \((x,y_w,y_l)\), definition:

\[
L_{DPO}=-\log\sigma\left( \beta\left[ \log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)} - \log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)} \right] \right)
\]

DPO has a close mathematical relationship with KL-Regularized RL, but typical DPO training:

- Do not allow the current Policy to be sampled online;
- Do not run the environment in the training ring;
- Do not train the scarar reward model separately;
- Only learn the chosen/rejected area covered by fixed data.

Therefore, the more accurate name of DPO is **Offline Direct Preference Optimization**, not Strictly Speaking Online RL. IPO, KTO, ORPO, etc. are also usually included in the direct preference optimization family.

### 14.1 When to use DPO first

- There are high-quality preference pairs, but there is no stable online Rollout system;
- The main goal is to align style, safety, help and other behaviors;
- Computing resources are limited;
- I hope to establish a stable baseline first, and then evaluate the increment of online RL.

### 14.2 When online RL is more valuable

- A large number of new samples can be evaluated at a low cost with Verifier;
- It is necessary for the current Policy to actively explore a new correct trajectory;
- Fixed preference data does not match the distribution of the current model;
- The task is a multi-step tool interaction, and decision-making must continue according to the environmental results.

## 15. On-policy, Off-policy and strategy are outdated

Strict On-policy requires samples from the current strategy. But in the actual system:

```text
Rollout Workers is generated with version v
-> Reward Workers Verification
-> Trainer has been updated to v+k
-> The old sample only entered the training
```

This will cause Policy Staleness. Common control measures include:

- Each round freezes \(\pi_{old}\), limiting the update of each batch of data Epoch;
- Limit deviations with Importance Ratio and Clip;
- Discard Rollout that exceeds the version difference threshold;
- Set the maximum age of Replay Buffer;
- Record the Policy Version of each sample in the synchronous or assembly line system;
- Monitor the difference between \(\pi_\theta\) and sampling log probability.

"Used Importance Sampling" does not mean that any old data can be safely reused. The distribution of long Sequence drifts faster than that shown by token Ratio.

## 16. A standard online RL training cycle

```text
Initialize Policy (Base / SFT / DPO Checkpoint)
Initialization can be selected Reference, Reward, Critic

for rollout_step:
1. Sample a batch of tasks from prompt Pool
2. Use the frozen Old Policy to generate G answers by temperature
3. Save token, Mask, Old LogProb, Policy Version
4. Run reward model / Verifier / Environment
5. Combine Reward and construct Advantage
6. Make some Mini-batch Policy Updates on the effective trajectory
7. Update or synchronize Old Policy
8. Run independent Eval, check Reward Hacking and ability regression
```

Each Rollout should be kept at least:

- Original prompt, chat template version;
- Generate token ID, but not only save the text of Re-Tonenize;
- prompt/Response Mask, EOS/Truncation status;
- Sampling parameters and random seeds;
- Old Policy token log probability;
- Each Reward component, Verifier version and failure reason;
- Policy Checkpoint/Version;
- Tool call, environmental observation and termination reasons.

## 17. Rollout distribution determines what the model can learn

### 17.1 Temperature is not an ordinary reasoning parameter

When the temperature is too low, the samples of the same question are almost the same, and there is no difference in the Reward in the group; when it is too high, a large number of garbled codes and meaningless tracks consume Verifier and token. Top-p, Top-k and Min-p will also change the actual exploration space of Policy.

During training, Sampling Config must be saved, and it is necessary to ensure that Old LogProb corresponds to **the distribution of real participation in sampling**. If Rollout does Top-k truncation, but Trainer calculates LogProb according to untruncated Softmax, the semantics of Importance Ratio are already inconsistent.

### 17.2 prompt Curriculum

Effective training questions are usually located at the ability boundary of the strategy: neither all right nor all wrong. Courses can be dynamically organized according to the success rate:

- Reduce the sampling frequency, but keep a small amount of anti-forgetfulness;
- Increase the weight of boundary questions;
- Pass the difficult problem first through SFT, decomposition or shorter sub-tasks;
- Continue to add unseen templates and anti-variants to prevent memorizing the answer format.

The dynamic course will change the target distribution, and finally Eval must be reported according to the fixed real distribution.

### 17.3 Group Size

Larger \(G\) can more reliably estimate the comparative advantage and increase the probability of finding the correct trajectory, but increase the generation cost. Should be compared jointly:

- Fix the number of Prompts and Group Size under the total generated token;
- `pass@G` and post-training `pass@1`;
- The actual calculation cost of each non-zero gradient Group;
- Is the big group just repeating the same pattern?

## 18. KL, Entropy and Exploration - Stable Balance

### Two common implementations of 18.1 KL

Sample-based KL can be estimated as Reward Penalty:

\[
r_t^{KL}=-\beta\left( \log\pi_\theta(y_t\mid s_t)- \log\pi_{ref}(y_t\mid s_t) \right)
\]

It can also be used as an independent regular term for training Loss. The gradient path and scaling of both are not exactly the same, and the configuration file must explain the specific implementation.

### 18.2 When can KL be weakened or removed?

Rule Verifier is not directly out of alignment due to Policy distribution drift like reward model, so some Reasoning RL formulas remove Reference KL, saving a Reference Forward. But it still needs to be evaluated:

- Whether the common language and command ability are forgotten;
- Whether the output is becoming more and more templated or lengthy;
- Whether safety behavior is degraded;
- Whether there are exploitable vulnerabilities in Reward;
- Whether the model only overfits the narrow Benchmark.

"Reward verifiable" does not automatically mean "no need for any behavior anchor".

### 18.3 Entropy

If Entropy is too low, it means that the sampling will be quickly determined and the exploration will be exhausted; if it is too high, it may be garbled, repeated and random trial and error. Should be jointly observed:

- Policy Entropy;
- Unique Response / n-gram Diversity;
- Reward, accuracy and output length;
- Up/Down Clip Fraction;
- The ratio of low-probability token to obtain positive Advantage.

It is not reasonable to pursue only the growth or decline of Entropy.

## 19. Length bias, truncation and Loss Reduction

In the long CoT RL, many "algorithm benefits" actually come from different weighting methods.

### 19.1 Three common Reductions

According to the answer, etc.:

\[
L_{seq}=\frac{1}{B}\sum_i\frac{1}{|y_i|}\sum_t\ell_{i,t}
\]

According to the valid token equal rights:

\[
L_{token}=\frac{\sum_i\sum_t\ell_{i,t}}{\sum_i|y_i|}
\]

Normalization according to fixed generation budget:

\[
L_{fixed}=\frac{1}{BC}\sum_i\sum_t\ell_{i,t}
\]

They make the weights of "each answer", "each token" or "position in the fixed budget" closer to the same. Without a record Reduction, the experiment cannot be reproduced.

### 19.2 Long answers are not equal to strong reasoning

The length increase may come from:

- Learn to develop useful derivations;
- Repeated self-examination;
- The wrong trajectory is punished weakly;
- The probability of terminating token decreases;
- Reward or Parser prefers text with more candidate answers;
- Max-length sample processing error.

At least the correct/wrong answer should report the respective length distribution, as well as Accuracy per token, not just the average length.

### 19.3 Truncate semantics

`EOS` and `max_tokens` are two completely different terminations:

- Natural EOS: Policy actively ends;
- Max-length: The system forced truncation, and the final answer may not appear yet;
- Environment termination: tool success, failure or timeout;
- Parser termination: get the legal final structure.

These states must be recorded separately in the training data. Don't fake EOS for the truncated answer, and don't assume that all truncated answers are logical errors.

## 20. Reward Hacking: Training success, goal failure

Common Reward Hacking includes:

- Math Parser only reads the last number, and the model outputs multiple contradictory answers;
- The code only passes through the public sample, and does not overwrite the hidden boundary;
- Judge prefers long, polite and titled answers;
- Tool Agent forged the "Execution Success" text without actually calling the tool;
- The model copies the Reference Answer or test information from the prompt leak;
- Use special characters, NaN or abnormal JSON to bypass the scorer;
- reward model scores increased, but real artificial preferences decreased.

Protective measures:

1. Verifier is executed in an isolated environment, and the model text cannot directly determine the success status;
2. Combination of hidden test, random test and confrontation test;
3. Reward content and real Eval indicators are recorded separately;
4. Regularly manually read the highest Reward, maximum reward growth and longest sample;
5. Use multiple independent Judges and calibrate with manual samples;
6. Do Fuzz Test on Parser;
7. Keep the unseen tasks and the unseen template Eval;
8. When Reward jumps abnormally, audit the trajectory first, instead of continuing to expand the training.

## 21. Cold Start, SFT and pure RL

### 21.1 Direct RL from base model

R1-Zero class training shows that under the appropriate base model, template, task and sampling budget, verifiable reasoning can be directly improved through RL. But it requires that Base Policy can occasionally explore the correct trajectory, otherwise there is no learning signal.

### 21.2 Reasoning Cold Start

First, use a small number of high-quality long CoT, format and tool trajectory to do SFT, which can usually:

- Establish a stable answer format;
- Reduce language confusion and unreadable output;
- Improve the initial positive Reward rate;
- Shorten the ineffective exploration stage of RL.

The price may limit the exploration style, or let the model imitate Teacher excessively. Cold Start data should be as diverse as possible, and use RL to verify whether it can exceed the demonstration distribution.

### 21.3 Multi-stage formula

A stable route is often:

```text
Base / Mid-training
-> General SFT
 -> Reasoning Cold Start
-> RLVR EXTENDS REASONING ABILITY
-> General Preferences / Security RL
-> Mixing capacity recovery and distillation
```

Every time we enter the next stage, we should keep the fixed regression set of the previous stage to prevent "mathematics become stronger and dialogue worse" from being covered up by the average score.

## 22. What Can Reasoning RL Actually Improve?

Outcome RL does not directly tell the model the correct reasoning steps, but changes the generation distribution by repeating sampling and strengthening the success trajectory. It may be promoted:

- Search among multiple candidate ideas;
- Decomposition problems and backtracking;
- Correct the answer after self-examination;
- Assign more Test-time Compute to difficult questions;
- Choose the expression that is easier to be confirmed by Verifier.

Maybe I can only learn:

- Longer fixed reasoning template;
- Benchmark specific answer format;
- Pattern memory of training question types;
- Invalid "Wait, I'll check again" text.

Therefore, it should be judged whether it is a real ability or a superficial behavior through difficulty extrapolation, anti-fact questions, disturbance questions, process inspection and Accuracy-vs-tokens curves.

## 23. Agent and Tool-use RL

Agent's trajectory is no longer a single answer:

```text
User
 -> assistant tool call
 -> Environment Observation
 -> assistant tool call
 -> ...
 -> Final Answer / Success / Failure
```

### 23.1 Status and Action

The status includes dialogue history, tool results, file or web page status; the action may be a natural language token or a structured tool call. Environment Transition is no longer completely determined by string splicing.

### 23.2 Reward Design

Can be combined:

- Whether the final task is completed;
- Whether the tool parameters are legal;
- Whether the correct tool has been selected;
- The number of calls, token and time cost;
- Whether to leak data or overpower;
- Whether the intermediate state is close to the target.

Don't just reward "the final answer claims to be completed", but must be judged to be the real completion from the environmental state.

### 23.3 Credit Assignment

Final Reward broadcasts directly to all Tool Calls, with a high variance. The optional methods include:

- PPO + Critic/GAE;
- Process Reward for each round or each tool step;
- Outcome-based Group Sampling;
- Locate the first irrecoverable error of the failure trajectory;
- Split the planning, tool selection and final answer into different Heads or stages.

### 23.4 The environment must be reproduced

Real web pages, searches or databases will change. The training system should record environmental snapshots, tool versions, time and return values; use Sandbox for write operations; use simulators or explicit approval for irreversible external actions.

## 24. System architecture of large-scale RL

There are at least four types of workloads in online RL:

```text
prompt/Data Workers
       ↓
Rollout Workers (high throughput self-regressive generation)
       ↓
Reward/Verifier/Environment Workers
       ↓
Trainer Workers (forward, reverse, optimization)
       ↓
Weight Sync -> Rollout Workers
```

### 24.1 Rollout is different from the calculation form of Training.

- Rollout attaches importance to KV Cache, Continuous Batching and Decode throughput;
- Training attaches importance to large token batch, Activation Checkpointing and distributed reverse;
- reward model is another set of reasoning services;
- Code/tool Verifier may be limited by CPU, container and I/O.

Therefore, the RL throughput is usually not "how many tokens per second for Trainers", but how many **valid training tokens with Reward differences** are generated per hour in the complete closed loop.

### 24.2 Synchronous and asynchronous

Synchronous system samples are fresher and the algorithms are clearer, but they will be dragged by the longest answer and the slowest Verifier; the high utilization rate of asynchronous system equipment will increase Policy Staleness and debugging difficulty.

### 24.3 Weight synchronization

The training framework and the reasoning engine may use different parallel cutting and weighting formats. To verify when synchronizing:

- All Layers are updated, and the LoRA/MoE weights are not omitted;
- tokenizer, chat template and Special token are consistent;
- The weighted version corresponds to Rollout Metadata;
- The LogProb difference of the same fixed input is within the tolerance range;
- BF16/FP8, quantization and Kernel differences did not change the sampling semantics.

## 25. The special problem of MoE model doing RL

MoE RL is more unstable than Dense:

- Policy updates to change the distribution of token, and also change expert Routing;
- The small Logit difference between Rollout and Training Kernel may trigger different Top-k Experts;
- A few high Reward models may be concentrated in a few Experts;
- Each expert has fewer valid tokens under the small batch;
- router Auxiliary Loss may not match the Scale of Policy Gradient.

Each layer should be monitored:

- expert token Count, load dispersion and maximum/minimum ratio;
- router Entropy, Dropped token;
- Routing distribution of different Rewards/fields/languages;
- Gradient Norm of router and expert;
- Rollout/Training LogProb Difference;
- The correlation between Policy Clip Fraction and routing switching.

It can compare and freeze router, reduce router LR, increase effective token batch, Sequence-level GSPO, and keep general data Replay. You can't judge whether router is healthy only by looking at the total Reward.

## 26. Training stability index

### 26.1 All online RL should be recorded

- Mean/Std/Quantile of each Reward component;
- Independent real Eval, not just training Reward;
- prompt, Response, correct/wrong answer length;
- EOS, Truncation, Invalid Format ratio;
- Policy Entropy, KL to Reference;
- Old/New LogProb Difference and Importance Ratio Distribution;
- Clip Fraction, it is better to distinguish between Upper/Lower;
- Advantage Mean/Std and non-zero ratio;
- Gradient Norm, parameter update norm and NaN/Inf;
- Rollout tokens/s, Train tokens/s, Verifier Latency;
- token cost of each effective gradient Group.

### 26.2 PPO Additional Record

- Value Loss;
- Explained Variance;
- The scale of Return and Value;
- GAE Mean/Std;
- Actor/Critic learning rate and update ratio;
- Value Clip Fraction.

### 26.3 Group-based algorithm additional record

- Group Reward Std;
- All-correct / All-wrong Group Ratio;
- The number of valid samples for each prompt;
- Dynamic Sampling retry times;
- Reward Diversity of Different Group Sizes;
- In-group repetition rate and diversity of answer patterns.

## 27. How should RL be evaluated?

### 27.1 Ability Indicators

- Mathematics/Code: pass@1, pass@k, strict accuracy and compilation/execution success rate;
- General dialogue: Pairwise Human/Judge Win Rate, and calibrate the position and length deviation;
- Agent: real task success rate, average steps, recovery rate and cost;
- Security: Harmful Compliance, Jailbreak Success, False Refusal;
- Format: Schema Validity, tool call Accuracy and Stop Correctness.

### 27.2 inference cost

The accuracy of Reasoning Model must be reported together with the output token:

\[
\text{token Efficiency}= \frac{\text{Solved Tasks}}{\text{Generated tokens}}
\]

Accuracy-Cost curves under different maximum token, Temperature and sample numbers should also be drawn. After training, the small improvement in exchange for the output of several times token may not be suitable for product deployment.

### 27.3 Generalization and contamination

- The source of the development set and the final test set are isolated;
- Accurate and approximate deduplication with RL prompt Pool;
- Use unseen question types, templates and languages;
- Training Verifier and evaluation Verifier are separated;
- Code tasks use hidden tests;
- Check the answer leakage and template memory for the public Benchmark.

### 27.4 Checkpoint Selection

Don't automatically select the model according to the highest point of training Reward. You should choose between capability, security, general maintenance and cost according to the predefined multi-target Scorecard, and keep the Pareto Frontier Checkpoint.

## 28. Common failure patterns and positioning

| Symptoms | Common Causes | Priority Troubleshoot |
|---|---|---|
| Reward rises, real accuracy does not rise | Reward Hacking or training/evaluation Parser is different | Highest Reward trajectory, hidden test |
| GRPO Loss Long-term close to 0 | Group All Right/All Wrong or Advantage Mask Wrong | Group Reward Std, Effective Gradient Rate |
| The output is getting longer and longer | Reduction bias, EOS penalty, truncated strategy error | The length of the positive and false samples is separated, EOS Logit |
| Entropy Rapid Collapse | Clip Upper Boundary Is Too Tight, Sampling Is Too Low Temperature, Topic Is Too Narrow | Upper Clip, Diversity, Temperature |
| Entropy is too high and garbled | Reward is too sparse, excessive exploration, KL is too weak | Reward density, KL, sampling distribution |
| PPO Value Loss Explosion | Reward Scale Drift, Mask/Bootstrap Error | Return, GAE, Terminal Mask |
| KL Sudden Jump | LR/Update Epoch Too Big, Old Rollout | Policy Version, Ratio, Clip Fraction |
| Actor can't learn but Verifier is normal | Base Policy never takes a positive sample | pass@G, course, Cold Start |
| Fast training, non-reproducible effect | Sampling Seed/Kernel/environment uncertain | Rollout Metadata, environment snapshot |
| Tool Agent claims success but the task is not completed | Reward reads the model text instead of the environment state | Success judgment link |
| MoE Minority expert Overload | router Drift or High Reward Mode Single | Hierarchical expert/Reward Routing Statistics |
| Online behavior regression | Only optimized narrow RLVR, no general/security anchors | Comprehensive regression set, Replay/KL |

## 29. How to choose an algorithm

### 29.1 Universal help, security and style alignment

Prioritize the establishment of a strong SFT + DPO baseline. If you have a reliable reward model and need to explore online, you can compare RLOO and PPO:

- Single round final Reward, resource sensitivity: try RLOO first;
- There are intermediate rewards and long multiple rounds of decision-making: PPO/Critic is more valuable;
- reward model is easy to misalate outside the distribution: Retain Reference KL and artificial regression.

### 29.2 Mathematics, Code and Formal Reasoning

Priority is given to RLVR:

- It needs to be mature and easy to achieve: GRPO;
- Pay attention to the length/difficulty normalization deviation: add Dr.GRPO ablation;
- Long CoT, large-scale training: evaluate the four formulas of DAPO;
- MoE or Rollout/Training LogProb is obviously inconsistent: compare GSPO.

Do not change base model, data, Verifier, Clip and Reduction at the same time to claim that an algorithm benefits.

### 29.3 Tool-use and Agent

- Short, resettable, only final success or failure: Group-based method can establish a baseline first;
- Long timing sequence, clear intermediate feedback: PPO + Critic/GAE is more natural;
- The environment is expensive: do offline trajectory SFT/DPO first, and then use a small amount of online RL;
- The environment will change: priority should be given to the problem of repreducible and safe execution, and then the optimizer will be discussed.

### 29.4 small model or limited computing power

Suggested order:

1. High-quality SFT;
2. DPO on fixed preference data;
3. RLOO/GRPO on small-scale, strictly verifiable tasks;
4. Confirm that Rollout does bring gains and then expand the Group, length and system complexity;
5. Finally, consider Critic, Multi reward model and Full Asynchronous Cluster.

## 30. A set of reliable RL experimental sequence

1. Freeze Base/SFT Checkpoint, tokenizer, Template and Eval;
2. Unit test Reward/Verifier, first use the correct and incorrect answers constructed manually;
3. Run pass@G for Base Policy to confirm that the positive Reward can be collected;
4. Set the fit with the very small prompt, and check the direction of Reward, Mask, LogProb and gradient;
5. Establish the minimum baseline of Vanilla REINFORCE/RLOO or GRPO;
6. Fixed total Rollout token, compare Group Size, temperature and topic courses;
7. Dissipate KL, Clip, Advantage Normalization and Loss Reduction respectively;
8. Then add Dynamic Sampling, Overlong Shaping and other combination skills;
9. At the same time, report the cost of training Reward, independence, security and token;
10. Manual audit high Reward, low Reward, longest and Reward jump samples;
11. Do multiple random seeds and intermediate Checkpoint evaluation;
12. After the algorithm is stable, the model, maximum length and asynchronous parallel scale are expanded.

The most important principle is: try to answer only one question in each round of experiments. RL closed-loop will amplify any data, reward and achieve differences.

## thirty-one. How does the industry's open route evolve?

### 31.1 InstructGPT: SFT + reward model + PPO

InstructGPT lays the foundation for the classic three-stage RLHF: manual demonstration of SFT, pair preference training reward model, and PPO optimization Policy under the constraints of KL. It is still the basic paradigm for understanding universal alignment RL.

### 31.2 Constitutional AI: RLAIF

Constitutional AI uses a set of principles to guide the model to generate criticism, revision and AI preferences, and then carry out supervised learning and RL. It shows that feedback can be extended by AI, but humans still need to define principles and evaluate deviations.

### 31.3 DeepSeekMath: GRPO

DeepSeekMath replaces the independent Critic with Group Relative Advantage, reduces the memory and system complexity of PPO, and pushes GRPO to mathematical reasoning training.

### 31.4 Tülu 3: SFT + DPO + RLVR

Tülu 3 put SFT, DPO and verifiable reward RL in the same post-open training route, indicating that offline preference optimization and online RLVR can be continuous stages, not mutually exclusive schemes.

### 31.5 DeepSeek-R1: Large-scale reasoning RL and multi-stage training

DeepSeek-R1-Zero shows that large-scale RL is done directly from base model; DeepSeek-R1 adds Cold Start and multi-stage training to improve readability, language mixing and general behavior. These two routes show that "pure RL is feasible" and "production formula is suitable for multiple stages" can be established at the same time.

### 31.6 DAPO: Public Long CoT RL System Details

DAPO combines asymmetric Clip, dynamic sampling, token-level Reduction and ultra-long sample processing into a reprocessable formula, emphasizing that the effect of reasoning RL comes from the joint effect of algorithms and system details.

### 31.7 GSPO: Sequence-level Optimization and MoE Stability

GSPO aligns Importance Ratio, Clip and Reward to Sequence granularity and openly emphasizes their stability in MoE RL training. It represents the trend of shifting from "compying general token-level PPO" to "redesigning optimization units according to the generation structure according to the language model".

## 32. miniLLM current implementation and RL evolution suggestions

### 32.1 What do you have now?

miniLLM currently implements the standard DPO:

- [`trainer/train_dpo.py`](../../trainer/train_dpo.py) Run Trainable Policy and Freeze Reference at the same time;
- [`dataset/dpo_dataset.py`](../../dataset/dpo_dataset.py) construct chosen/rejected Pair, and only score the final assistant answer;
- [`eval/eval_dpo.py`](../../eval/eval_dpo.py) Compare DPO Policy with SFT Reference;
- [`dataset/rl/dpo.jsonl`](../../dataset/rl/dpo.jsonl) provides fixed preference pairs.

This belongs to offline preference optimization, not the online RL defined in this article: there is currently no Policy Rollout, Reward/Verifier, Advantage estimation, Old Policy version or environmental closed loop.

### 32.2 How to understand the existing RL data files

According to the current file sample:

- [`dataset/rl/rlaif.jsonl`](../../dataset/rl/rlaif.jsonl) is mainly multi-round `conversations`, and the last assistant is empty; the file name itself cannot make it RLAIF, and you still need to clarify AI Feedback, candidate answers and scoring fields;
- [`dataset/rl/agent_rl.jsonl`](../../dataset/rl/agent_rl.jsonl) contains `conversations` and `gt`, which can be used as some task prompt/Verifier raw materials, but need to convert Ground Truth, tool execution and success judgment into strict environmental interfaces.

Before there is no class-by-class audit of data semantics, it should not be sent directly to RL Trainer based on the file name.

## thirty-three. The final conclusion

The main line of the large model RL can be compressed into four layers:

```text
Feedback Layer: Human / AI / Verifier / Environment
Reward Layer: Outcome / Process / Multi-objective Reward
Optimization layer: PPO / RLOO / GRPO / DAPO / GSPO
System Layer: Rollout / Reward Service / Trainer / Weight Sync
```

The core of algorithm selection is not to chase the latest abbreviation, but to match the task structure:

- Subjective preferences require reliable reward model, KL and manual calibration;
- Verifiable reasoning is suitable for Critic-free Group-based RL;
- Long CoT must audit Reduction, length and truncation;
- Multiple rounds of Agent require real environmental status and more refined Credit Assignment;
- MoE also needs to deal with routing drift and reasoning - training LogProb inconsistency;
- Any training Reward must be bound by an independent real Eval.

PPO provides a general Actor–Critic basis, RLOO and GRPO reduce the cost of Critic, Dr.GRPO and DAPO expose the importance of Loss Reduction and sampling details, and GSPO further raise the optimization unit to the Sequence level. A truly reliable RL system ultimately depends on the correct reward, data exploration, verification and self-deception.
