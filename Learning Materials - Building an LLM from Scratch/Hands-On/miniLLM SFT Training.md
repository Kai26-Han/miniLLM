# miniLLM SFT Training

> Stage: full-parameter supervised fine-tuning of the pretrained miniLLM

> Default recipe: `sft_mini.jsonl`, sequence length 768, learning rate 1e-5, two epochs, and assistant-only loss

---

## 1. What SFT Teaches the Model

Pretraining teaches the model to predict the next token from the context to its left. SFT then teaches it to:

- understand system and user instructions;
- respond as an assistant;
- conduct multi-turn conversations;
- emit an explicit reasoning structure when required;
- initiate tool calls in the agreed format; and
- output `<|im_end|>` after the response and stop.

SFT neither retrains the tokenizer nor starts from random parameters. The training entry point must load the Transformers model directory exported by pretraining.

```text
Pretrained model: out/pretrain
        +
conversation JSONL
        ↓
ChatML / reasoning / tool-calling template
        ↓
Apply loss only to assistant tokens
        ↓
Full-parameter SFT + MoE router auxiliary loss
        ↓
out/sft + checkpoints/sft/latest.pt
```

## 3. Data format

Each line must contain a `conversations` array:

```json
{"conversations":[
  {"role":"system","content":"You are a reliable AI assistant."},
  {"role":"user","content":"Explain what gradient descent is."},
  {"role":"assistant","content":"Gradient descent is an optimization algorithm...","reasoning_content":"Explain the goal first, and then explain the update process."}
]}
```

The supporting roles are:

- `system`: System instructions, only as context;
- `user`: user input, only as a context;
- `assistant`: Model output, participate in Loss;
- `tool`: The tool returns the value as a context only.

Optional fields:

- `reasoning_content`: render to `<think>...</think>`;
- `tools`: function definition list or its JSON string;
- `tool_calls`: The function call to be generated by assistant.

### 3.1 assistant-only Loss

The complete dialogue will input the model, but only the assistant output and `<|im_end|>` participate in the cross-entropy:

```text
system/user/tool/header/padding → label = -100
assistant reasoning/content/tool_call/EOS → label = token_id
```

The model itself will stagger the logits and labels left and right to calculate the next-token loss.

### 3.2 Long conversation interruption

When exceeding `--max-seq-len`:

1. Keep the system message at the beginning;
2. Delete the earliest complete dialogue round from the left;
3. Try to keep the latest user/assistant interaction;
4. If the latest round itself still exceeds the upper limit, give priority to the optional long reasoning, keep the latest prompt context, assistant Header and final answer; if the answer is still too long, keep the beginning of the answer, and do not forge the EOS that ended early;
5. Log `truncated_ratio` and `answer_truncated_ratio`.

### 3.3 Training set and validation set

`--val-ratio 0.001` is used by default. The data set is divided into training sets and verification sets through deterministic global subplacing controlled by random seeds. There is no need to save index arrays in memory for 5.1 million data. At the same time, a limited number of verification samples can overwrite different data sources before and after the file. The same data file and `--seed` will be exactly the same.

## 4. Start training

First, confirm that the pre-training model has been exported:

```text
out/pretrain/
├── config.json
├── model.safetensors
└── tokenizer files...
```

The default parameters have been solidified into the mini data scheme with good verification effect this time. Single-card formal training:

```bash
python trainer/train_sft.py \
    --model-path out/pretrain \
    --tracker swanlab
```

six-GPU training:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5 \
torchrun --standalone --nproc_per_node=6 trainer/train_sft.py \
    --model-path out/pretrain \
    --tracker swanlab
```

Effective global batch Size:

```text
Global_batch = batch_size × accumulation_steps × GPU quantity
```

The default single GPU configuration is `4 × 4 × 1 = 16` sequences/update; the six-GPU configuration is `4 × 4 × 6 = 96` sequences/update.

Full data is no longer the default approach. If you need to do full experiments specifically, explicitly pass in `--data-path dataset/sft/sft.jsonl`, and use independent `--save-dir` and `--output-dir` to avoid covering the model of the mini data scheme.

## 5. Do smoke training first.

Before the official operation, it is recommended to check the data, Loss Mask, GPU memory and save links:

```bash
python trainer/train_sft.py \
    --model-path out/pretrain \
    --max-train-samples 1000 \
    --eval-samples 100 \
    --max-steps 20 \
    --batch-size 2 \
    --accumulation-steps 2 \
    --eval-interval 10 \
    --save-interval 10 \
    --tracker none
```

Key observation:

- Whether `loss` and `lm` are finite values;
- Whether `assistant_tok/s` is continuously output;
- Whether `pad_eff` is reasonable;
- Whether the truncation ratio is too high;
- Is MoE's `aux` abnormally large;
- Whether `checkpoints/sft/latest.pt` and `out/sft` are generated correctly.

### 5.1 Loss Appears NaN

The trainer will actively stop in three places instead of continuing to write bad models:

1. After loading the model, check whether all pre-training parameters contain `NaN/Inf`;
2. Check the total Loss, LM Loss and router Loss before each backpropagation, and output the limited value statistics of the corresponding JSONL original line number, sequence length, supervised token number and Logits;
3. BF16/FP32 Check whether the gradient norm is limited before updating.

If the first log is `loss=nan lm=nan aux=nan`, you should stop it immediately and do not use the checkpoint of this SFT to continue training. First, use a single GPU and a single step to reproduce:

```bash
CUDA_VISIBLE_DEVICES=0 python trainer/train_sft.py \
    --model-path out/pretrain \
    --data-path dataset/sft/sft_mini.jsonl \
    --max-train-samples 64 \
    --eval-samples 16 \
    --max-steps 1 \
    --batch-size 1 \
    --accumulation-steps 1 \
    --num-workers 0 \
    --tracker none
```

- If you report `Pretrained model contains non-finite model state` at startup, go back to the pre-training checkpoint that is still normal for Loss, and re-export `out/pretrain`;
- The default `float32` baseline will explicitly turn off TF32, and the startup log should show `Precision: float32` and `TF32: disabled`;
- SFT does not enable gradient checkpoints by default to avoid introducing recalculation paths in the front of the baseline. Only when the baseline is stable but the GPU memory is insufficient, `--gradient-checkpointing` will be added;
- If it only fails on some data, check the corresponding JSONL row according to `source_jsonl_rows`.

Dynamic Padding batch should use the default Eager attention:

```bash
python trainer/train_sft.py --attention-backend eager
```

Eager back-end explicitly constructs cause and effect and Padding Mask, and completes Q/K/V projection, RoPE, attention Score, Softmax, Value aggregation and output projection in float32; all Padding hidden state will be cleared after embedding and after each residual block. It occupies more video memory and is slower than fusion SDPA, but it will not allow the invalid position of dynamic Padding to participate in cross-layer numerical propagation. `auto` and `math` are only recommended to be used without Padding batch or after full stability verification.

The trainer will automatically do a module-level NaN/Inf check on the first forward, and remove the hooks immediately after passing, without affecting the subsequent throughput. Only by adding `--debug-numerics` will the check be retained in each batch, which is only applicable to the diagnostic operation of persistent numerical problems.

The RoPE frequency is not saved as `persistent=False` buffer, but is generated on the real computing device according to the configuration certainty. This avoids the meta-device initialization path of Transformers `from_pretrained` instantiates the RoPE buffer that is not written to the checkpoint into uninitialized data.

## 6. checkpoint to resume training

Automatically restore the default checkpoint:

```bash
python trainer/train_sft.py --resume
```

When restoring, the completed batch will be skipped directly in the batch sampler layer, and the trained data will not be re-read and tokenized. For example, `Resume data: skipping 192,000 completed batches at sampler level` in the log indicates that the recovery location has been directly applied, not re-scanning 192,000 batches.

Restore the specified checkpoint:

```bash
python trainer/train_sft.py \
    --resume checkpoints/sft/latest.pt
```

The two types of loading have different meanings:

| Parameters | Meaning |
|---|---|
| `--model-path out/pretrain` | Only load the pre-training structure and weights to start a new SFT |
| `--resume checkpoints/sft/latest.pt` | Restore SFT model, optimizer, Scheduler, Scaler, training position, random state and Tracker |

When resuming training, key parameters such as data, batch, gradient accumulation and total training steps should be kept consistent.

## 7. Evaluate

At the same time, calculate and verify Loss and generate answers:

```bash
python eval/eval_sft.py \
    --model-path out/sft \
    --mode both
```

Only test generation:

```bash
python eval/eval_sft.py \
    --model-path out/sft \
    --mode generate \
    --prompt "Please explain what the attention mechanism is."
```

Open the explicit thinking prompt:

```bash
python eval/eval_sft.py \
    --model-path out/sft \
    --mode generate \
    --open-thinking \
    --prompt "Prove that the root number 2 is an irratal number."
```

If you want to test the function call, you can prepare a tool definition file:

```json
[
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "Check the weather",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
      }
    }
  }
]
```

Then run:

```bash
python eval/eval_sft.py \
    --mode generate \
    --tools-json tools.json \
    --prompt "How's the weather in Shanghai today?"
```

## 8. Default hyperparameter

| Parameters | Default Value |
|---|---:|
| data_path | dataset/sft/sft_mini.jsonl |
| epochs | 2 |
| max_seq_len | 768 |
| batch_size | 4/GPU |
| accumulation_steps | 4 |
| learning_rate | 1e-5 |
| min_learning_rate | 1e-6 |
| warmup_ratio | 0.0 |
| weight_decay | 0.01 |
| AdamW betas | (0.9, 0.95) |
| grad_clip | 1.0 |
| dtype | float32 |
| attention_backend | eager |
| gradient_checkpointing | false |
| val_ratio | 0.001 |
| eval_samples | 2048 |
| empty_think_ratio | 0.2 |
| system_prompt_ratio | 0.2 |

The model structure, MoE expert number, Top-K, RoPE and router auxiliary loss coefficients are all inherited from the pre-training model configuration and are not redefined in the SFT command.
